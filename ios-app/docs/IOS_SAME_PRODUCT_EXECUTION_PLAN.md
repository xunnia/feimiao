# 肥喵记账 iOS 同款执行合同

更新时间：2026-08-31

## 1. 唯一目标

Android 是产品、信息架构、业务字段、账务口径和功能范围的唯一母版。iOS 是同一款“肥喵记账”的原生实现，不是第二款相似软件。

iOS 可以使用 SwiftUI、Liquid Glass、系统控件、原生键盘、转场和触觉，但不得：

- 删除、替换或改名 Android 的主入口；
- 改变主页、抽屉、记一笔、设置和二级页面的信息层级；
- 用“有页面”“有按钮”“有 PNG”代替真实功能闭环；
- 让金额、分类、账户、账本、日期、退款、报销、预算、统计或净资产结果与 Android 不一致；
- 把 Apple 平台限制伪装成已实现。确无系统权限的能力必须提供最接近的替代入口并明确说明差异。

## 2. 当前审计结论

| 口径 | 当前估计 | 依据 |
|---|---:|---|
| 源码功能覆盖 | 70%–75% | 165 个 Swift 文件、48 个页面文件、34 个测试文件；主要功能域已有实现 |
| 已证实同款 | 50%–55% | 141 个测试标记覆盖核心规则，但双端运行态逐字段和操作链证据不足 |
| 可交付完成度 | 35%–40% | 真机、签名、真实网络/OAuth、恢复、扩展和后台能力未闭环 |

不能继续沿用的旧证据：

- 39/39 只证明声明的 PNG 文件存在且可解码；不证明路由、数据或功能正确。
- `23-import-review.png` 实际显示首页，属于真实路由缺陷。
- 旧 Android parity 多张 PNG 含大面积透明像素，拼图显示黑底，不能用于视觉判断。
- 旧 fixture 在 Android 运行日生成额外房租，造成两端金额不一致；修复后尚无完整双端最终报告。
- Android 的“对账/负债”等场景曾用资产资金页代替目标页面，不属于同场景证据。
- iOS 工程版本曾停留在 1.270.0+284；本轮已对齐当前 Android 工作版本 1.281.0+295。

## 3. 分阶段执行

### P0 证据链与路由

- Android 所有截图路由使用真实应用背景，禁止透明/黑底/裁切；原始 PNG 不覆盖。
- iOS 冷启动路由逐项测试；导入复核直接进入真实页面。
- 每张图检查尺寸、alpha、内容区、目标页面身份和关键 fixture 文本。
- 同名场景必须是同一业务页面；禁止用“相近页面”顶替。
- 固定同一语言、时区、日期、币种、账本、账户、分类和交易 fixture。
- 输出原始 Android、原始 iOS、逐对对比图和总览联系图。

关闭门：39 个现有场景全部真实可读、页面身份正确、金额字段一致；新增转账、退款、删除、预算承诺、恢复等操作后状态。

### P1 核心账务同款

- 首页：顶栏、账本切换、月份、预算、最近账目、筛选、底部记一记入口一致。
- 记一笔：支出/收入/转账、表达式、两级分类、常用排序、账本、账户、标签、日期、备注、附件、待报销、不计入一致。
- 明细/搜索：按天卡、净额、筛选、编辑、删除、退款/报销徽章一致。
- 退款/报销：附着原单、原日期归属、结算账户/日期、部分/全部、撤销和级联一致。
- 账本/账户/分类/标签/对账：保护规则、排序、归档、余额与校准一致。
- 周/月/年/自定义统计：窗口、空白日期、分类排行、趋势和净额一致。

关闭门：同一 fixture 逐字段 JSON 断言；正常、空、错误、取消、重复提交与操作后状态都有自动测试和成对截图。

### P2 完整功能同款

- 预算：计划版本、周期、分类额度、固定承诺、专项追踪、历史修订和退款复核完整闭环。
- 导入/备份：真实微信/支付宝/CSV/XLSX、重复检测、商户组、退款配对、Android v48+ 完整备份、媒体、失败回滚。
- 存钱/定时：规则、到期物化、幂等、归档和关联资产一致。
- 资产/负债/净资产：档案、成本关联、估值、折旧、生命周期、还款本息、权益、快照、质量状态完整。
- 报告/AI：多服务商、多账号、多模型、Effort、Chats、附件、来源、记账提案、撤销、任务、记忆、技能、搜索、定时报表一致。

关闭门：每个功能域至少一条真实副作用操作链，不以 mock 或静态页面代替。

### P3 iOS 系统能力与交付

- Widget 四类、App Intents、Share Extension、OCR、Speech、通知、BGTaskScheduler。
- ChatGPT/Codex OAuth、模型目录、Responses/Claude/兼容端点在真实账号和真实网络验证。
- Dynamic Type、VoiceOver、深色模式、Reduce Motion、输入法、安全区、权限拒绝与恢复。
- Xcode 26/27 模拟器构建、XCTest、Release device 构建、完整/无扩展 IPA、哈希和重签说明。
- iPhone 真机安装、冷启动、升级/恢复、Widget、分享、权限、后台、网络和回调。

平台硬边界：iOS 无第三方通知全局读取权限、不能自行替换 App 二进制、后台执行不保证固定时刻。这些只能用分享/OCR/快捷指令、本地通知和前台补算做同目标替代，不能声称与 Android 系统权限相同。

## 4. 每次交付的强制门禁

1. 当前分支和精确 diff；不得混入 Android 其他会话改动。
2. Swift 格式/编译、QingJiCore、App XCTest；记录实际测试数。
3. Android/iOS 同 fixture 逐字段对账，不只比较截图。
4. 所有变更页面的原始前后截图、双端对比图和总览图。
5. 关键操作验证数据库或文件真实变化；失败/取消后状态不被污染。
6. 版本、Bundle ID、IPA 内容、签名边界、SHA-256 和回退基线。
7. 未运行或未通过项明确写“未验证”，不能降级成完成。

## 5. 接续顺序

任何模型/会话接手都从 P0 未关闭项继续，不重新设计产品。机械实现可以交给快速模型；账务口径、迁移、恢复、OAuth、安全和跨平台差异必须先按本合同审计再改。
