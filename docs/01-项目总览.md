# 01 项目总览

> 回答「这是什么产品、做什么不做什么、哪些决定已经锁定、谁拍板、代码怎么分」。

## 1. 一句话

**肥喵记账**：面向个人用户的记账 App。外观可爱，交互安静，账务严谨。吉祥物是用户家的蓝白英短猫，对标咔皮记账。

| 项目 | 信息 |
|---|---|
| Android（主交付平台） | `android-app/`，Flutter + Dart + Provider + SQLite(sqflite) + 原生 Worker/Widget |
| Android 包名 | `com.qingji.qingji.codex`，min SDK 24，compile/target SDK 36 |
| iOS | `ios-app/`，原生 SwiftUI，是 Android 的同款原生实现，见 `09-iOS.md` |
| 仓库 | `https://github.com/xunnia/feimiao`（主分支 `main`） |
| 本机工作目录 | `C:\src\xunni-codex`（`C:\src\xunni` 是旧工程，未经用户确认不要动） |
| 更新分发 | 自建 VPS，见 `05-构建与发布.md` |

## 2. 用户问题

让普通用户低负担地完成这些闭环：

- 快速记下收入、支出、退款、报销和转账；
- 知道本周期花了多少、还能安排多少；
- 看懂账户、资产、负债和净资产，不需要会计背景；
- 导入外部账单后能核对、纠错和回退；
- 使用肥喵统一管理的 AI，无需理解服务商、模型或接口配置，同时清楚必要的数据使用范围；模型/思考强度选择与自定义接入仅属于内部管理能力（2026-10-02 用户再次明确）；
- 任何页面看到的数字一致、可解释、可追溯。

**价值排序**（冲突时按这个取舍）：

1. 数据不丢、金额算对；
2. 结果可解释、状态诚实；
3. 高频记账足够快；
4. 同类交互保持一致；
5. 增强能力按需出现，不把专业复杂度推给所有用户。

## 3. 范围

已在范围内：

- 手动、快捷、AI、自动（通知）、定时记账；分享到肥喵；截图识别；
- 退款、报销、转账、不计入收支、导入复核；
- 多账本、分类（两级）、标签、账户、存钱目标；
- 预算规则（日常预算、特别安排、自然月日历、月底结余）；旧分类预算、固定预留和专项追踪已停用，不恢复；
- 统计、报告、桌面小组件、AI 查账与喵助手；
- 资产物品、估值、处置、账户校准、负债、净资产核对；
- 完整本地备份、导入导出、应用内更新与历史版本回退；
- 肥喵统一管理的 AI 与数据使用告知；内部管理保留多服务商、模型/思考强度选择、GPT OAuth 和账号 JSON 导入。

暂缓或不做：

- **多人共享账本**：方向已解锁（2026-07-02 用户决定），但需要账号、后端、同步冲突和权限模型，必须单独立项，不夹带在其他批次里；
- 严格多币种折算（首要币种 CNY）；
- 银行账户自动聚合、证券交易引擎、企业会计；
- 语音记账（国产 ROM 没有谷歌语音，要做得接云端 ASR）；
- 分类图标颜色自定义编辑。

## 4. 锁定的产品决策（定了别反复）

改动下面任何一条都要用户明确拍板。

**视觉与交互**

- 可爱风路线，吉祥物是蓝白英短猫（`lib/widgets/mascot.dart`，真图在 `assets/mascot/`）。
- 猫系配色：主色蓝灰 `#7D8B9B`、铜金 `#F2B23C`、粉 `#F4A9B8`、超支橙 `#FF9F68`、奶白底 `#FFFDF7`。
- 收支语义：收入是铜金，支出是中性深色，超支和危险是橙色。**不用红色**；绿色只允许用于预算健康态。细则见 `06-UI设计标准.md`。
- **没有底部 Tab 栏**：单主页 + 左侧推开式抽屉（学 Claude）。这一条已被多次否决改动。
- 同类同设计：同一平台的弹窗、分段、按钮、开关、日期选择统一公共组件。两端功能、入口、信息层级与结果一致；**iOS 原生设计更好的地方优先用原生**，尤其 Liquid Glass、菜单、确认框、sheet、选择器和系统无障碍（2026-10-02 用户明确）。不为复刻 Android 自绘外壳遮住原生材质，也不把全 App 做成玻璃内容卡。
- **喵助手聊天前端（2026-10-04 用户明确）**：以 Claude iOS 的设计与交互为主要参考，Pi 仅作为后续补充；可靠性修复不额外增加「继续生成」按钮。中断保留已有正文及轻说明，恢复沿用已有重新生成入口；逐项对齐阅读、附件、来源和菜单，不凭源码或 Android 离屏图宣称已还原 Claude iOS。
- **长期品质目标（2026-10-03 用户确认）**：Android/iOS 以 Awwwards、The Webby Awards、FWA 获奖作品的完成度为目标，每批主动自查、修正、复验，直到当前范围的品质门禁真正满足。执行标准见 `06` §9；不以内部评分保证获奖，不照搬展示型网页，也不牺牲数据可靠性、记账性能、原生优势或锁定决策。当前单批测试/截图通过不等于全 App 已达目标。

**数据与计算**

- **本地优先**：能在本机做的优先在本机做，核心记账和统计没网也能用。这是「优先」，不是「绝对不上云」（2026-09-29 用户澄清）。云备份、后端读云端账本生成报表这类功能可以做，但要让用户单独同意，并写进隐私政策。
- **统计单一真相源**：页面不能各算一套，所有指标服从 `07-统计口径标准.md`。
- **未知不能伪装成 0**：缺日期、缺估值、有冲突或覆盖不全时，返回 partial/unavailable 等真实状态。
- **冲减归原家族**：退款、报销、红冲的日期归属原交易所在月份，不能作为新收入漂到别的月份。
- **账户余额全局**：余额不因账本筛选而消失；归档不等于从净资产里删除。
- **版本只前进**：versionCode、数据库版本、口径版本各自单调递增，互不代替。

**AI 与隐私**

- **正式普通用户端**：AI 由肥喵统一管理，用什么模型、思考强度由我们按用途/档位在后台决定。普通用户没有模型/强度选择、服务商添加、自定义地址、API Key、OAuth 或账号 JSON 导入入口；不能把现有自用版界面当作未来普通用户界面。
- **内部管理端**：保留多服务商（DeepSeek、OpenAI 兼容接口、GPT OAuth、Claude 等）、BYOK/OAuth、模型/强度选择及诊断，只有经服务端授予内部权限的账号可见。free/pro/max 会员不能解锁这些内部入口。上线转换方案单独制定，不静默删除现有配置或凭据。
- **当前自用阶段与后续配置方式（2026-10-02 用户补充）**：现在不关闭、隐藏或删除用户正在使用的 AI 服务商功能。正式普通端以后隐藏配置 UI，但保留底层服务商配置和调用能力；会员专属用户 Key 由后端自动下发，App 自动填入既有 AI 服务商配置，基础地址指向我们服务器的 Sub2API，让用户无需手工配置即可使用。供应商主 Key/OAuth 不下发，现有自用配置不被静默覆盖；具体请求入口、字段及账号隔离按后端契约对齐。会员权限、模型范围及额度由服务端校验，不以隐藏 UI 代替准入控制。
- **两池与稳定凭据（后端会话 2026-10-02 同步，未接入）**：用户只有主池和记一记专用池；日常 AI 记账使用专用池，其余用户主动 AI（聊天、查账、分析、批量归类、主动报告）共用主池，两池不自动借用，多 Key/模型/分组不额外发额度。注册周锚点不变，会员旧周超额不扣新周。App 复用同一 Sub2 `users` 身份；用户 Key 正常开通、续费、升档、到期复用，泄漏可轮换。最新确认的到期、自动钱包补充与 Key＋App 会话规则见下条；Key 数量不固定，free 数额、钱包费率/币种/非会员模型、凭据头名仍待契约冻结，不能写成已上线。后端 S3 统一网关准入验收前，不向正式 App 下发可调用凭据；当前自用能力保留。契约评估入口与阻塞见 `02` §7.9。
- **到期、资金与调用身份（同日后端最终通知，已确认、未实现）**：到期立即结束该档付费功能和剩余周池，回仍有效低档，否则 Free；沿用回落档同周已用量、不重复赠额，钱包独立保留、稳定 Key 不变。相应用途池耗尽而钱包可用时自动补充，不要求两池全空、不增加必需开关，也不恢复到期会员功能。一笔入场选定池后不临时改扣钱包；池剩 0.01、尾单 0.03 时扣 0.01、免除 0.02，下一笔才可使用钱包。所有肥喵 AI 新请求要求同用户 Key＋有效 App 会话，并检查设备撤销；仅 Key 不可调用，已准入在途请求仍按旧快照结算。会话只发往可信肥喵服务，不附加第三方 BYOK；具体头分配以后端 API 契约为准。
- **原生 Key 与并发补充（同日最新确认，未接入）**：App 复用 Sub2 `users.id`，后端按会员角色的分组订阅和用途替本人创建原生 `api_keys`。较早本人网页登录查看 Key 的讨论已被最新登录渠道限制收窄：自己的 App 密码不得直接登录 Sub2 网页；管理员随机网页密码是候选，默认禁用肥喵用户网页登录是后端建议、尚未批准，不混同原生 Key 所有权与 App 普通端隐藏配置 UI。Key 数量不固定为两把，角色新增路由可按需补齐，仍只共享两池。用户默认总并发 **5**、会员角色可配置，跨设备/Key/两池/入口统一执行，App 读服务端值，不写死旧值 2。主池耗尽不全局禁用记一记。截图三种处理方式、离线 OCR、内部 BYOK 和交易对方/商品字段的两端对齐保留在后续契约检查中；接口与 Responses/Chat Completions 协议未冻结前不改当前调用。
- AI 数据使用告知采用轻量方式，不在日常聊天/记账时反复弹窗；真实接收方与数据范围仍应明确，超出已取得许可的范围时需在发送前完成必要更新。具体告知形式、隐私能力的入口与位置，要先参考 Claude iOS 的整套页面设计，再与用户对齐；不直接锁定当前「隐私与数据」行的位置。密钥不进备份、日志和 Git。
- 本地 OCR（ML Kit）对密集订单列表页有识别上限。要做到更准得上云端视觉模型，这需要用户同意。

**账号与设置（2026-09-29 用户定，账号功能随后端改造上线）**

- 「我的」就是设置页，名字仍叫「设置」，整体参考 Claude iOS。不另做第二个「我的」页；设置顶部加账号区，账号细节（邮箱、密码、登录设备、导出个人信息、注销）放在新写的账号子页。
- 抽屉入口改成左下角「头像 + 昵称」，点击进设置（替代原来的齿轮），两端一致。
- 用量卡片照 Claude 的样式做：百分比进度条 + 重置时间；免费档不显示额度。打开设置时刷新一次权益，离线显示上次更新时间。
- 购买方式（2026-09-29 修订，用户在后端会话里定，经同事会话转达）：
  - 安卓：App 内只有兑换码，码由服务端生成；其他购买方案另行设计。
  - iOS：照 Claude iOS 做 Apple 内购自动续期订阅，价格从 StoreKit 取；设置页有「升级」「管理订阅」「恢复购买」。iOS 不出现兑换码，也不提 App 外的购买渠道。
  - 安卓兑换的会员登录 iOS 同样生效。细则见后端 `docs/04` 阶段 E。
- 登录设备列表只做一个组件：登录时设备超限和账号页「登录设备」共用。
- 头像和昵称本机保存，同时上传到后端，换设备能恢复。
- 昵称最多 12 个字（按看到的字算，一个 emoji 算 1 个），安卓、iOS 两端一样（2026-09-29 用户定）。服务端允许 20 字，App 只用 12 字；别的地方存了更长的名字，拉回本机时截成 12 字。两边不一致时按修改时间取新的。
- 云备份方向：安卓备份到自有服务（VPS 或 Cloudflare 存储），iOS 走 iCloud。退出登录、注销的提示要写清本机账本和云端备份各自怎么处理。
- iOS 补齐「使用条款」「隐私政策」入口，并去掉「无账号」文案。
- AI 设置页按行删减：
  - 「AI 账号设置」（BYOK/OAuth 等）正式方向是只给内部账号；普通用户即使未登录也不提供配置 UI，但底层配置和调用能力保留，由 App 自动接收会员专属 Key 并配置肥喵 AI。当前自用阶段仍保留正在使用的全部入口，不提前关闭。早期访客入口不是正式普通端方案（2026-10-02 用户再次明确并补充过渡方式）。
  - 隐私与数据能力保留，说明统一面向「肥喵 AI 服务」；入口、命名、分组和页面位置待参考 Claude iOS 整体设置方案后定，不机械沿用当前五行 AI 分组。
  - 任务中心和诊断合在一起，只给内部账号。
  - 删掉统一搜索、技能与连接页、本地模型伴侣，两端都删。删技能页时把各技能开关恢复为开，判断一并去掉；联网搜索只留聊天 [+] 里那一个开关。
  - 「可控记忆」和「喵学到的分类」合成一页「记忆」。
  - 删完以后取消「AI 记账设置」子页，改成设置首页的「AI」分组。
- 定时报表由后端管（方案 C）：用什么模型、什么时候推送都由后端决定，后端读云端账本生成报告。这依赖云备份先做好；云备份上线前，保留现在本机的定时报表。
- iOS 双备份（v2）：iCloud 照常备份，另外上传一份报表用的账本数据到我们服务器。管理规则如下：
  - 手机本机账本是唯一真相；iCloud 是 iOS 的恢复来源；服务器这份只用来生成报表，不用来恢复，免得出现两个恢复来源互相打架。
  - 只传报表需要的字段（净额、分类、日期、账户、备注），不传收据图片。两端上传同一种格式。
  - 增量上传，删除也要同步到服务器，这依赖删除墓碑（02 第 22 条）。
  - 设置里显示「云端报表数据」：开关、上次上传时间、一键删除云端数据。关掉就停止上传，删除后 30 天内删干净。
  - 提示要写清：删除 iCloud 备份不会删服务器这份，反过来也一样。
  - 上传开关跟账号绑定：换账号登录后开关自动关闭，退出登录后停止上传。
  - 一个账号同一时间只认一台设备上传（两端账本互相独立，同时上传会重复计算）。别的设备要开启时，先问用户要不要把上传来源换成这台。
  - 不计入统计的账在本机过滤掉，不上传；已经传过的账后来改成不计入统计，就传一条删除记录。原账补了退款或报销、净额变了，也算更新；全额退款、净额为 0 的照样上传。
  - 备注和账户名里连续 12 位以上的数字，上传前打码。
  - 删除提醒走邮件，设置页显示「X 天后删除」。
  - 接口和字段以后端 `docs/01` §18 为准。

**工程铁律**

- Release 构建关闭 R8（`isMinifyEnabled=false`、`isShrinkResources=false`）。打开会裁掉 ML Kit 反射加载的类，截图识别直接崩。
- 不写 `repeat()` 永动画；纯色背景上的 GlassSurface 用 `blur: 0`（手机发烫的教训）。
- 外部 AI（GPT/Gemini 等）给的评审只挑增量。它们常推底部 Tab、红绿配色、强制云同步，这些与上面的决定冲突，不采纳。

## 5. 角色与决策权

| 角色 | 权责 |
|---|---|
| 用户（产品负责人） | 定优先级、视觉偏好、范围解锁、真机验收、是否发布 |
| 实施代理（Claude / Codex 等） | 读现状、提可验证方案、实现、测试、验包、记录风险；不擅自扩大范围 |
| 审查者 | 找行为回归、数据风险、隐私问题、缺失测试和文档错误；不用个人偏好推翻锁定决定 |
| CI | 跑可重复的 analyze/test/build 门禁；CI 绿不代替真机验收 |

以下动作必须先取得用户明确授权：

- 发布到线上、改 VPS 或更新服务、推送远端、创建正式 Release；
- 重写 Git 历史、强推、删除远端分支；
- 删除用户账本、签名材料、备份或不可再生的验收证据；
- 改变已锁定的产品方向、统计公式或隐私默认值；
- 引入需要长期付费、账号体系或新后端的外部依赖。

## 6. 代码地图（Android）

| 路径 | 职责 | 修改注意 |
|---|---|---|
| `lib/core/` | 纯领域逻辑：AI、预算、资产、统计、备份、安全、更新 | 优先写纯逻辑测试，不依赖页面状态 |

| `lib/theme/` | 主题、颜色、字体、尺寸令牌 | 服从 UI 标准，页面不写死全局颜色 |
| `android/` | Manifest、签名、Worker、Widget、原生通道 | 需要 Android 构建和原生行为验证 |
| `test/` | 单元、Widget、Repository、迁移、回归测试 | 数据高风险改动必须补反例 |
| `ci/` | 验包、发布、门禁脚本 | 改脚本要跑它自己的测试 |
| `outputs/` | 历史 UI 与验收证据 | 不是缓存，不要整目录删 |

架构约束：

- `AppRepository` 是集中式数据入口，文件很大、耦合高。新的共享公式先落在 `core` 的 resolver 里，再由 Repository 适配，不要继续往里塞页面算法。`ai_chat_panel.dart`（约 1 万行）同理。
- SQLite 是本地财务真相源。迁移必须幂等、事务化、能从任意旧版本连续升级，风险升级前自动备份（`pre-v*`）。
- WorkManager、通知、Widget 这类后台消费者，必须读取与前台相同的持久化数据，不能依赖只在内存里的页面状态。

## 7. 数据治理

**金额与事件**

- 持久化和核心计算用整数分或 Decimal，禁止用浮点直接累加金额。
- 原交易与它的退款、报销组成交易家族，消费统计读家族净额。**喂给 AI 的也必须是净额**，不能是毛额加散落的明细。
- 归属日期、结算日期、估值日期、知识截止时间是不同的轴，不能用一个 `date` 代替全部。
- 转账、校准、资产处置、负债变化不能为了「看起来有记录」伪造成普通收支。

**结果质量状态**：`available`（完整）、`partial`（部分，列明遗漏）、`unavailable`（缺关键证据）、`conflict`（来源矛盾，禁止静默挑一个）、`notApplicable`、`stale`。UI 禁止用 `null ?? 0` 把这些状态统一显示成 0。

**数据库迁移门禁**（每次 DB 版本变更都要满足）：

1. 写明旧版本、目标版本、字段默认值和旧数据语义；
2. 不伪造无法证明的日期、余额、汇率、估值或账户归属；
3. 一次升级能连续跑完所有中间迁移；
4. 迁移在事务内完成，失败不留半套 schema；
5. 覆盖「旧库升级、重复初始化、备份恢复后升级、核心金额前后等价」；
6. 高风险迁移前自动创建 `pre-v*` 备份；
7. 降级安装不保证安全，回退方案要说明 APK 与数据库是否兼容。
