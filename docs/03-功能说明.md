## 一、App 结构总览

**一句话**：单主页 + 左侧推开式抽屉，**没有底部 Tab**。

- **主页顶栏**：左 ☰ 打开抽屉（也可在主页向右拖开）；中间是当前账本快切胶囊（点开切账本）；右 🔍 进搜索。
- **主页底部输入框「记一记」**：
  - `[+]` 和喵助手同一张「添加到聊天」面板：相机 / 最近照片 / 全部照片 / 添加文件 / 工具权限 / 联网搜索。选好图片或文件后直接打开 AI 记账，附件已放进输入框，可再补一句话发送（手动模式也会切到 AI，因为手动记账看不了图）；
  - 导入导出只在抽屉「导入导出」里；
  - 模式胶囊：手动 ⇄ AI 直接切换，记住上次选择；
  - `↑` 或点输入框：打开记账弹层，弹层内也能在手动/AI 间切换。
- **抽屉功能项**（注册表 `lib/main.dart` 的 `_kDrawerFns`，key 用来持久化排序，**不要改已有 key**）：
  统计数据 / 资产管理 / 预算管理 / 存钱目标 / 喵助手 / 分类管理 / 标签管理 / 导入导出 / 待报销 / 定时记账 / 自动记账。
  - 默认只露前 5 项，「更多」展开其余；长按可拖动排序（`repo.setDrawerOrder`）。
- **抽屉「我的账本」**：
  - 最早建的账本 = 总账本（`defaultBookId`），不可删；其他账本的账单是否汇入总账本由「账单计入总账本」开关决定。
  - 每行 ⋯：加星 / 编辑 / 删除（改名在「编辑」弹层里，不单列）；⋯ 可点区域 48dp。
  - 删除保护：没账单 → 普通确认；有账单 → 推荐「转移并删除」（账单挪到总账本）；拒绝转移 → 再一次「永久删除」确认。
- **抽屉底部**：左「头像 + 昵称」= **设置**（全 App 唯一设置入口，底部弹层；没设昵称时显示「设置」）；右「新建账本」（名称、备注、封面模板、计入总账本开关）。和 iOS 一致。
- **设置页分组**：
  - 资料卡（昵称/头像）；
  - AI：AI 账号、记忆、定时报表、任务与诊断、隐私与数据（登录后「AI 账号」「任务与诊断」按服务端开关显示，见 §5；没登录和默认构建全部显示）；
  - 管理：备份与恢复；
  - 显示：账单与聊天显示（内容优先/分类优先、用户气泡样式）、主题外观、金额显示；
  - 提醒：还款提醒；
  - 小组件：隐藏金额；
  - 关于：检查更新、历史版本、关于（使用条款/隐私政策）。
- **主要文件**：`lib/main.dart`（RootShell、抽屉 `_DrawerPanel`）、`lib/views/home/home_view.dart`、`lib/views/home/record_input_bar.dart`、`lib/views/settings/settings_view.dart`、`lib/views/books/book_sheet.dart`。

## 二、记账

### 2.1 手动记账卡
- **入口**：主页输入框（手动模式）；编辑任何一笔账单也进这张卡（编辑模式）。
- **布局（自上而下）**：
  1. 支出 / 收入 / 转账（转账只在新建时有）；
  2. 分类网格：每行 5 个，最多露 2 行，多出来的上下滑（这时右侧常驻细滚动条提示）；点有子类的大类，原位展开二级面板，其余区域模糊；
  3. 芯片排：日期 / 账本 / 账户 / 标签 / 待报销（仅支出）/ 不计入；
  4. 金额卡：金额 + 备注 + 相册/拍照附图；
  5. 键盘：`1-9 ⌫ + − 再记 0 . 完成`。
- **规则**：
  - 金额支持 `+ −` 连加连减；连按两个运算符以后按的为准（`12+` 再按 `−` 变 `12-`）；算式太长整体缩小显示，不截断；
  - 「再记」= 保存后不关卡继续记，「完成」= 保存并关闭；「再记」后的「已记 ¥x」提示显示在备注框的占位文字里，备注框随时能输入；
  - 不能保存时（没输金额、合计 ≤ 0、没有账户、转账账户不对）点「完成/再记」会弹提示说原因，不会没反应；
  - 编辑模式：完成键变「保存」、没有「再记」、不能切账本；转账编辑时类型锁定。
  - 转账：只留日期/账本芯片，用扣款⇄入款两个账户框（按内容定高）；只有一个账户时提示先去资产管理加账户；转账不算收支。
  - 账本/账户下拉菜单：选中项用统一菜单件的浅底 + 对勾。
- **分类树**：`lib/core/models/category_seed.dart`。
  - 支出 11 个一级：食品餐饮、购物消费、出行交通、车辆支出、休闲娱乐、居家住房、医疗健康、教育学习、保险保障、人情家庭、其他。
  - 收入 11 个一级：工资薪酬、奖金奖励、副业收入、投资理财、养老金、家庭支持、礼金红包、经营收入、退款报销、其他收入。
  - 子类约 99 个。
  - **铁律**：分类 `key` 稳定不变（历史账单靠它），改名只改显示名；隐藏的分类不出现在记账面板。
- **主要文件**：`lib/views/home/manual_add_sheet.dart`、`lib/views/quick_add/amount_keypad.dart`、`lib/views/quick_add/category_grid.dart`、`lib/core/amount_expression.dart`。

### 2.2 AI 记一记（主页 AI 模式）
- **是什么**：一句话（如「午饭 28」）→ 大模型解析成结构化账目 → 记账卡。
- **入口**：主页输入框切到 AI 模式。它和 Chats 里置顶的「记一记」会话是同一套（`AiChatPanel(recordOnly: true)`）。
- **自动入库规则**（`lib/views/home/ai_chat_panel.dart` + `lib/core/ai/ai_tool_registry.dart`）：
  - 直接记 + 可撤销：只有 1 笔、金额 > 0、置信度 ≥ 0.9、不需要追问，且工具权限不是「按需加载」。
  - 停在提案卡等你点：多笔（≤5 笔）、低置信、或「按需加载」。
  - 普通聊天会话里要写账，一律先确认。
- **记账卡**：
  - 改分类芯片：改完会写入学习记忆，下次同类备注自动用这个分类。
  - 删除芯片；卡片跨重启保留（已保存的卡）。
- **兜底与校验**：
  - 没配 AI 或请求失败 → 本地规则解析（`natural_language_entry_parser.dart`，认中文数字金额）。
  - 金额/日期合理性校验：`entry_sanity.dart`。
  - 商户词典：`merchant_category.dart`；餐次推断：`meal_time.dart`；报销/AA：`smart_tags.dart`；比平时贵很多会提醒：`spending_anomaly.dart`。
  - 分类优先级「用户记忆 > 词典 > 大模型 > 兜底」来自旧文档，**待核实**是否仍完全如此。
- **GPT 记账**：走流式 Responses。只有收到完整、合法的结构化结果才入账；中途断流或不完整就整体失败，不会记半截。
- **主要文件**：`lib/views/home/ai_chat_panel.dart`、`lib/views/home/record_entry_sheet.dart`、`lib/core/ai/llm_entry_parser.dart`、`lib/core/ai/chat_intent.dart`。

### 2.3 喵助手 / Chats
- **入口**：抽屉「喵助手」→ Chats 列表页。
- **会话列表**：
  - 顶部固定「记一记」（记账专用，不能改名/删除）；
  - 其余是普通聊天：新聊天、搜索、筛选（全部/加星）、长按 加星/重命名/删除；
  - 每个会话记住自己的模型选择。
- **能做什么**：查账问答（带必要的账本上下文）、闲聊/知识问答、生成周报/月报/年报。
  - 说「生成月报」之类会生成 Markdown 报告，存进报告库（会话页右上角入口）。
  - 报告任务可后台继续，重开 Chats 能恢复。
- **加号面板**（`lib/views/home/chat_add_sheet.dart`）：

  - 工具权限三档：
    - 自动：按问题自动选工具；
    - 按需加载：写账先确认；
    - 始终可用：全部工具都可用。
    - 覆盖的工具：账本查询与统计、记账与分类、图片识别、联网搜索。
  - 联网搜索开关：没有原生搜索的服务商走 DuckDuckGo 公开摘要，**不带账本数据**（`lib/core/ai/web_search.dart`）。
- **⋯ 菜单**：
  - 聊天记录保存时长：一周 / 一个月 / 三个月 / 半年 / 永不删除；
  - 删除当前会话的记录。

### 2.4 支付截图识别
- **入口**：只剩「分享到肥喵」分享来的图片。
  - 主页 `[+]` 选图不走这条本机OCR，而是把完整图片内容交给AI记账模型看图（本地候选必要时准备质量优先副本、原图保留；需要配好AI key，模型要能看图；失败会明说原因、保留消息可重试，不会假装记好）。
  - 不做「模型看不了图时先本机 OCR 再交给 AI」的兜底（2026-09-29 用户决定：他配置的模型都能识图）。
- **流程**：本机 ML Kit 中文 OCR（不联网）→ 判断是不是订单列表 → 是就按「共N件」切单（整单丢弃已取消/退款/未付款）→ 交给 AI 快记页解析 → 你确认后才入账。
- **边界**：
  - 京东/淘宝整页订单列表 OCR 本身不稳（丢 ¥、认错数字、行序乱），**做不到分毫不差**；
  - 单个订单详情页基本准。
  - 整页列表当「批量草稿」，在确认页删改兜底。
- **构建铁律**：release 必须保持 `isMinifyEnabled=false`、`isShrinkResources=false`（`android/app/build.gradle.kts`）。否则 R8 会裁掉 ML Kit 靠反射加载的类，识别时直接崩溃。
- **主要文件**：`lib/views/quick_add/screenshot_entry.dart`、`lib/core/ai/order_list_parser.dart`、`lib/core/ai/screenshot_layout.dart`、`lib/views/quick_add/ai_quick_entry_view.dart`。
- 喵助手和主页 AI 记账里发的图片：不走 OCR，直接以图片发给模型（`llm_entry_parser.dart` 的 `_chatAttachmentParts`，已核对代码）。

### 2.5 分享到肥喵
- **是什么**：在别的 App 里「分享」→ 选肥喵。
  - 文字 → 进 AI 快记页；
  - 图片（单张/多张）→ 走截图识别。
- **规则**：
  - 冷启动时分享可能比数据库先到，先排队，数据就绪后再处理；
  - 初始化失败时暂停，恢复后继续。
  - 队列只在进程内保留，App 被杀会丢，**不跨进程持久化**。
- **主要文件**：`lib/share_intake.dart`、`android/app/src/main/kotlin/com/qingji/qingji/MainActivity.kt`（MethodChannel `feimiao/share`）。桌面小组件的跳转也走这里分发。

### 2.6 自动记账（支付通知）
- **入口**：抽屉「自动记账」→ 授予「通知使用权」+ 保活引导。
- **流程**：
  1. 原生通知监听**只看微信（`com.tencent.mm`）和支付宝**的支付通知；
  2. 粗筛后排进本机队列；
  3. 回到前台弹「喵盯到几笔消费」确认表，勾选后一键记下。
- **规则**：
  - **不静默入账**；
  - 用户保存或忽略后才按 ID 从原生队列删除；
  - 两笔同价消费不会被当成重复吞掉。
- **主要文件**：`lib/core/auto_record.dart`、`lib/views/auto_record/auto_record_sheet.dart`、`lib/views/settings/auto_record_setting_view.dart`、`.../kotlin/com/qingji/qingji/PaymentNotificationListener.kt`、`lib/core/notification_parse.dart`。

### 2.7 定时记账（周期记账）
- **入口**：抽屉「定时记账」。可新增、编辑、启停、删除规则。
- **规则**：
  - 频率：每天 / 每周 / 每月 / 每年；
  - 月、年会夹到月末（31 号在短月记到月底，不溢出到下月）；
  - 编辑时能预览接下来几次的执行日。
  - 到期由仓库在启动时自动生成账单（首屏前处理）。
  - 房贷/分期向导生成的是「转账」型规则（每月自动还款），表单里只能改转出/转入账户。
- **主要文件**：`lib/views/settings/recurring_view.dart`、`lib/core/models/recurring_rule.dart`。

### 2.8 导入账单 + 导入复核
- **入口**：抽屉「导入导出」→ 导入账单；主页 `[+]` → 导入账单。
- **格式**：
  - CSV / TXT / XLSX / XLS：微信、支付宝（含 GBK 编码）、咔皮、木木等，按列名模糊匹配；
  - 肥喵自己导出的 CSV：按原样恢复，并跳过重复；
  - JSON：用于恢复实物资产/权益等资产数据包。
- **导入复核页**（确认后才入库）：
  1. 每行先自动归类：先查学习记忆，再用分类器；
  2. 没归上的按「归一化商户」分组，点一次就能给整组定分类（会顺便学习）；
  3. 也可点「AI 归类剩 N 个」，一次批量调 AI（可选，需要配置 AI）；
  4. 退款行按「商户订单号」挂回原单，让净额归零；找不到原单的退款直接丢弃，不造负数。
  - 0 元行、不计收支行（提现、花呗还款等）会跳过。
- **分类原则**：看「买了什么」，不看「谁卖的」。
  - 京东/淘宝/美团这类平台商户只落安全的一级默认分类，也不会被学成子类；
  - 瑞幸、滴滴这类决定性商户可以信任商户名。
- **主要文件**：`lib/views/settings/import_export_view.dart`、`lib/views/settings/bill_review_view.dart`、`lib/core/import/bill_import.dart`、`lib/core/ai/bill_categorizer.dart`。

### 2.9 退款 / 报销 / 转账 / 不计入收支
- **入口**：账单行左滑 → 编辑 / 退款 / 删除（`lib/widgets/transaction_actions.dart`）。
- **退款（附着式）**：给原单挂一笔负支出（`refund_of` 指向原单），不在时间线单独显示。
  - 原单显示：划线原价 + 净额 +「已退 X」。
  - **退款行的记账日期 = 原单日期**：冲减归属原单所在月，否则跨月会把统计算错。
  - 另外要选实际到账日和到账账户，用于资金流。
  - 上限是剩余可退金额；删除原单时一起删掉它的退款。
- **待报销**：
  1. 记账时打「待报销」；
  2. 抽屉「待报销」按净额汇总；
  3. 点「已报销」：选到账日和账户，补一笔冲减让净额归 0，并清掉标记。
  - 不是只清标记。
- **不计入收支**：账单留在列表里并加灰标，统计和预算跳过它。它和「待报销」是两件独立的事。
- **转账**：两个账户之间挪钱，不算收入也不算支出。
- **主要文件**：`lib/data/app_repository.dart`（`refundTransaction` / `markReimbursed` / `visibleTransactions` / `netAmountOf`）、`lib/core/ledger/ledger_policy.dart`、`lib/widgets/refund_settlement_sheet.dart`、`lib/views/transactions/reimburse_view.dart`。

### 4.1 预算

### 4.2 资产管理（账户 / 资产 / 负债）
- **入口**：抽屉「资产管理」。
  - 资产管理是**全局范围**，账本只是物品/权益的归属信息。
  - Android 顶部三个视图：**总览 / 资金 / 物品**。
- **右上角「添加」**：
  - 账户：现金、银行卡、信用卡、存款、贷款；

- **总览**：净资产主卡、资金资产/计入物品/总资产/总负债四小卡，共享历史区间；保留待处理、可信核对和资产结构。净资产为全局范围，不与本月收支混算。
  - Android本地候选将重复估算说明集中到主卡右上信息入口，数据缺口仍在卡内摘要提示。缺估值历史不参与连线或涨幅，稳定排除同一币种的部分估算仍可比较已覆盖范围；变化不是收益率。详见02 §7.23（未发布）。
  - 下半页本地候选：「上次核对」明确历史日期/完整或部分核对，信息入口可看冻结金额、全部缺口和比较原因；资产结构用分类金额＋真实占比，多类别细构成条、单类别不画重复图。partial/零分母/金额口径不一致不展示伪比例。只有总览显示不带金额符号，其他流程不改；见02 §7.24（未发布，iOS源码未编译且缺全局可信核对能力）。
- **资金 Tab**：
  - 账户详情与流水；
  - 净资产核对（可撤销上次）、懒人盘点；
  - 借贷页：借出/收回、借入/还款；

- **物品 Tab**：

  - 可关联存钱目标。
- **负债口径**：每个账户有负债余额模式，避免历史上「账户余额 + 负债档案」双算。旧账户默认保留老算法，由迁移向导切换（`lib/core/account/liability_balance_mode.dart`）。
- **资金可靠性补修（2026-10-04，本地候选，未发布）**：还款读取最新账户实际欠款拆本金/利息，旧混合口径冲突时先核对，不自动改历史。本金转账和利息支出关联同一事件；Android账单左滑只提供整次「撤销」，iOS负债详情用原生菜单撤销，不能单独删改、退款或报销。本次权益收回同步到账流水和剩余权益，本金不进普通收入，撤销时一起恢复；凭证缺失、资料变化或余额核对已吸收该笔时拦截，不只恢复一边。Android回归与iOS编译状态见02 §7.26。
- **还款提醒**：设置里开关。开启后在还款日前一天 20:00、当天 10:00 各提醒一次，非精确闹钟，允许小误差（`lib/core/assets/repayment_reminder.dart`）。
- **币种**：退款、报销的到账账户要求 CNY / 和原单同币种。多币种不在范围内，**待核实**其他路径是否也只支持 CNY。

### 5.1 服务商 / 模型 / Effort
- **服务商**：
  - DeepSeek 内置，不可删；
  - `+` 可添加任意多个自定义服务商。
  - 每个服务商可设：认证方式（API Key / OAuth 授权）、上游格式（自动 / Chat Completions / Responses / Anthropic Messages）、基础地址、名称、普通模型；
  - 可「获取模型」「验证账号」「测试连接」。
- **模型管理**：
  - 从上游拉取列表，可逐个删除；再次拉取只增量加入新模型；
  - 模型身份 = (服务商, 模型名)，不同服务商可以有同名模型。
- **地址规则**：
  - 任意合法 HTTPS 都可以；
  - HTTP 只允许本机、私网（如 192.168.x.x）、链路本地地址；
  - 公网 HTTP、非 http(s) 协议、带用户名密码的地址会被拒。
  - 设置页和请求层用同一套校验，JSON 导入也绕不过（`lib/core/ai/ai_provider_url_policy.dart`）。
- **选模型**：在输入框左侧点模型按钮，按服务商分组显示。
  - Effort 六档：Low / Medium / High / Extra / Max / Ultra；旧数据里的「关闭 / Minimal」会归一到 Low。
  - 请求时按端点映射到它支持的最高档。
- **谁用哪个模型**：
  - 主页「记一记」和 Chats 置顶「记一记」共用输入框里选的模型和 Effort；
  - 其他聊天会话各自保存自己的选择。
- **主要文件**：`lib/views/settings/ai_setting_view.dart`、`lib/core/ai/ai_provider_config.dart`、`lib/core/ai/ai_http_transport.dart`、`lib/core/ai/ai_request_manager.dart`。

### 5.2 GPT OAuth
- **是什么**：用 ChatGPT 账号登录，不用 API Key。
- **流程**：
  1. 官方浏览器 PKCE 授权，回调到 `localhost:1455`（备用 1457）；
  2. Android 原生保活监听回调，能扛 Activity 重建和重复回调；
  3. 浏览器显示连接失败时，可以手动「粘贴回调地址」。
- **登录成功后**：
  - Token 先存进本机安全存储；
  - 再拉官方模型目录，并用第一个模型发一个不带账本内容的最小探测。
  - 模型目录失败时账号仍保留，健康状态分阶段记录。
- **地区限制**：遇到 `unsupported_country_region` 时，交给本机浏览器完成换 Token（走浏览器的 VPN），code/verifier 不进入 URL。
- **不再默认用**：设备码流程。
- **主要文件**：`lib/core/ai/openai_codex_oauth.dart`、`.../kotlin/com/qingji/qingji/OAuthKeepAliveService.kt`。
- **待核实（真机）**：Chrome 账号选择、手机 VPN 出口、localhost 回调。

### 5.3 AI 账号 JSON 导入 / 导出（Cockpit 兼容）
- **入口**：AI 账号设置 → 导入账号 JSON / 从剪贴板粘贴 JSON / 导出账号 JSON。
- **导入**：
  - 支持 Cockpit 完整备份与单账号导出、OpenAI `auth.json`、Sub2API、JSON/JSONL、BOM/UTF-16；

- **导出**：Cockpit 兼容格式，**包含敏感凭据**，导出前会二次确认。

## 六、数据安全

**基本前提**：数据都存在本机 SQLite（`qingji.db`），**没有云同步和账号体系**。多人共享账本是已放开的长期方向，但尚未开工。

### 6.1 备份与恢复
- **入口**：设置 →「备份与恢复」。
- **导出备份**：生成 `.zip` 完整包（格式 v2），包含数据库、票据图片和资产图片，并逐文件校验。**不含 AI 密钥**。
- **从备份恢复**：
  - 选 `.zip`，也兼容旧的 `.db` / `.bak`；
  - 会替换全部账目，恢复前自动留一份 `.bak` 兜底；
  - 恢复在后台做，会逐文件校验，并防护异常体积、条目数和不安全路径。
- **本机备份列表**：可「立即备份」，点任意一条可恢复到那个时间点。
  - 每周自动静默备份：`qingji.db.auto-日期.bak`；
  - 数据库升级前自动备份：`qingji.db.pre-v旧版本.bak`，失败不拦启动；
  - 本机最多保留 3 份。
- **主要文件**：`lib/views/settings/backup_view.dart`、`lib/core/backup/backup_package_codec.dart`、`lib/data/app_repository.dart`（`_autoPeriodicBackup`、`_backupBeforeMigration`）。

### 6.2 导入导出
- **导出**：当前账本导出为 CSV，可选时间范围（默认本月）。
- **导入**：见 2.8。
- **删除类保护**：删账本、删分类的保护见 一、4.4。

### 6.3 应用内更新 / 历史版本
- **检查更新**：设置 →「检查更新」。
  - 读 VPS 上的 `https://updates.xunni.dpdns.org/version.json`，本机 versionCode 更小才提示；
  - 用系统下载器下载，跨启动可以继续；
  - 必须通过 SHA256 校验才交给系统安装器：元数据和响应头都没有哈希时拒绝，非法哈希也不放行。
- **历史版本**：设置 →「历史版本」。
  - 读 `rollback.json`，只列出安装序号**高于**当前包、且签名校验过的回退包；
  - 原因：Android 不允许降级安装，回退包是用更高 versionCode 重新打包的旧版，账本数据会保留。
- **规则**：同包名、同签名才能覆盖安装。发布流程见 `05-构建与发布.md`。
- **主要文件**：`lib/core/update/app_update.dart`、`lib/views/settings/app_update_flow.dart`。
- 该文件顶部注释仍写「Cloudflare Worker/KV」，属于过时描述。

## 八、已知限制与待真机验证项

**真机与测试**
- **没有在线 ADB**：v1.298 的安装、冷启动、强停后重启，以及 GPT 中转流式记账都没在手机上实测。
- **全量测试有 1 条未过**：预算历史断言，期望 3000 实际 3100。这是既有问题，目前**不是**绿色发布门禁。
- **GPT OAuth**：Chrome 账号选择、手机 VPN 出口、localhost 回调、国区 403 浏览器兜底，都需要目标手机复测。

**能力边界**
- **截图识别**：京东/淘宝整页订单列表只能明显改善，做不到 100% 准；要 100% 得上视觉大模型，而用户明确要纯本地。
- **自动记账**：通知文案解析和国产 ROM 保活，是最大的不确定因素。
- **分享队列**：只在进程内，App 被杀后未处理的分享会丢。
- **小组件**：各家桌面上的显示效果未验收。
- **多币种**：不支持（退款/报销要求 CNY 或同币种账户）。

**未完成**
- **同步地基**：已有 uuid / updated_ms，但删除还没有墓碑，将来接共享账本后端时要补。
