# 04 开发规范

> 怎么接活、怎么干、怎么验、怎么交接。构建、发布、版本号的机械步骤看 `05-构建与发布.md`。

## 1. 开工前

1. 读 `docs/README.md` → `02-项目进度.md`；涉及的领域再读对应标准（UI 看 06，统计看 07，预算资产看 08）。
2. 执行 `git status --short --branch`。工作树里可能有用户或别的代理没提交的改动，**禁止 reset/checkout 覆盖未知修改**。
3. 用户一次发来多条需求、并说「先记录，说开始再做」时，只记录和澄清，不动代码。

需求至少要弄清楚：用户问题、期望行为、参考图参考的是什么（结构、风格还是逐像素）、明确不做什么、影响范围（UI/数据/统计/AI/原生/发布）、验收用例、优先级。

**优先级**

| 级别 | 定义 |
|---|---|
| P0 | 数据损坏、金额错误、隐私泄露、无法启动或安装、签名/发布回退风险 |
| P1 | 核心流程不可用，或用户明确点名的高优先级体验问题 |
| P2 | 明显影响效率、一致性或可理解性，但有绕行办法 |
| P3 | 增强、探索、长期能力 |

同级别下按「数据正确性 > 隐私安全 > 高频主流程 > 一致性 > 装饰性」排。

## 2. 批次纪律

- 一个批次解决一个完整的用户问题；紧密耦合的两个阶段可以合成一个 APK。
- 同一时间最多一个 DB 迁移批和一个发布候选。
- **实现、验证、文档一起结束**，不把半成品留给下一个会话去猜。
- 给出提交或推送命令后，用户执行期间不要开始破坏性大改（曾经因此把改到一半的文件提交进去，CI 挂掉）。
- 状态要分清：代码写完 ≠ 测试通过 ≠ APK 验包通过 ≠ 用户真机验收 ≠ 已上线。**本地 APK 不能写成已上线，没真机不能写成真机通过。**

## 3. 按风险选验证

| 变更 | 最低验证 |
|---|---|
| 文案或单一布局 | 相关 analyze、必要的 Widget 测试、文字溢出检查 |
| 纯领域逻辑 | 单元测试，含反例和边界 |
| Repository / SQLite | 单元 + FFI Repository 测试 + 迁移等价测试 |
| 统计 / 预算 / 资产 | 口径反例、整数分守恒、退款/日期/范围/partial 状态 |
| AI 服务商 / 隐私 | 重启持久化、同名模型、切换服务商、无 key、授权重置、密钥净化 |
| 公共组件 | 受影响页面回归，窄屏、大字号、深色主题 |
| Android 原生 / 后台 | Android 构建，通道/Worker/通知/Widget 专项测试 |
| 发布 | 见 `05-构建与发布.md` 的完整门禁 |

**完成（Done）的标准**：

- 行为满足需求，异常、空态、加载、禁用、删除、重启都处理了；
- 没有另造统计公式或第二套 UI；
- 新逻辑有相称的测试，**没有靠删旧测试来变绿**；
- analyze 无 error，新 warning 要么处理、要么解释；
- 当前状态、更新日志和必要的标准文档已更新；
- 没把 APK、缓存、密钥、日志误提交；
- 属于本任务的构建或测试进程都已结束。

## 4. 代码规则

- **UI**：先对照 `06-UI设计标准.md`，有公共组件必须用，没有就先造组件再用。改了 UI 要交前后对比图（规范见 06 第 8 节）。
- **统计**：改公式先改 `07-统计口径标准.md` 和反例测试，再改实现和 UI。
- **数据层**：迁移、退款/报销、统计口径是红线，改之前要有迁移测试和备份方案。任何「扫全库改写历史数据」的想法都先停下来问用户。
- **性能**：不写 `repeat()` 永动画；纯色背景上的 GlassSurface 用 `blur: 0`；长列表用 `.builder` 懒加载。
- **新文件不要继续堆进** `app_repository.dart` / `ai_chat_panel.dart`，新逻辑落到 `core/` 的独立文件。
- 异步回调要处理 `mounted`、重复提交、数据库未就绪。

## 5. Git 规则

- 精确 stage 相关文件，**禁止 `git add .` / `git add -A`**。
- APK、AAB、keystore、`key.properties`、日志、`build/` 永远不进提交。
- 提交信息用中文描述式，带版本号，例如 `修复启动完整性边界 v1.293.0+308`。
- 一个提交对应一个能说清楚的批次。
- **`main` 是唯一集成主线**。新工作从最新 `origin/main` 开 `codex/<任务>` 或 `claude/<任务>` 分支（CI 都会跑），验证后合入 main。
- 不要为了消除 ahead/behind 数字去 merge 旧历史分叉；迁移时历史被重写过，数字不代表实际差异，要比文件内容。
- 旧分支（`rescue/*`、`wip/*`、iOS 候选）里的有效改动逐项移植，不整支合并；全部进入 main 或有独立归档后才删分支。
- 主工作目录有在途改动时，在独立 worktree（如 `.tmp/<任务>`）里集成，不 reset/clean 原目录。
- CI 只上传构建产物（Artifacts），不自动提交生成结果回分支。APK/IPA、截图输出、SDK、缓存不进 Git。
- 包名、数据库名、源码 namespace 里的 `qingji` 是升级兼容标识，不因品牌整理改名。
- 推送、强推、改历史、删远端分支都要用户授权。

## 6. 协作与子代理

- **允许使用子代理**：并行检索、调研、按明确规格施工、独立审查都可以派出去。主会话负责拆任务、定规格、合并结果、最终验证。
- 同一个文件同一时间只让一个代理改。让子代理写代码时说明白范围，禁止它删除或覆盖范围外的文件。
- 子代理的结论要主会话核对以后才能写进文档或告诉用户，不能原样转述未验证的结论。
- Claude 和 Codex 可能交替接手同一工作树：开工先 `git status`，不覆盖对方未提交的改动；完成后把结果写进 `02-项目进度.md` 和 `10-更新日志.md`。
- 超长会话会让额度消耗突增。上下文很大时先把交接写进文档，再开新会话，新会话只读文档、不依赖旧聊天。

## 7. 文档维护（每批必做）

| 发生了什么 | 更新哪里 |
|---|---|
| 任何有意义的批次 | `10-更新日志.md` 顶部加一条；`02-项目进度.md` 看板和待办 |
| 新功能或功能行为变化 | `03-功能说明.md` |
| 构建、发布、版本规则变化 | `05-构建与发布.md` |
| 视觉规则变化（需用户拍板） | `06-UI设计标准.md` |
| 公式或口径变化 | `07-统计口径标准.md` |
| 产品方向、范围、锁定决定变化 | `01-项目总览.md` |
| iOS 进展 | `09-iOS.md` |

改完文档后运行同步脚本，镜像到 Obsidian（见 `README.md`）。**不要再新建交接文件、任务书或 `xxx报告.md`**：临时调研结论要么并进上面的文件，要么在对话里给用户看完就丢。

## 8. 本地环境

- Flutter SDK：版本 Flutter 3.44.2 / Dart 3.12.2，路径里不要有中文或空格。
  - ⚠️ 默认的 `C:\src\flutter` 目前是坏的：`bin/internal` 为空，`flutter --version` 直接报错。修好之前，用独立 SDK `C:\src\xunni-codex\.tmp\flutter-audit-sdk\flutter\bin\flutter`。
  - 这个目录属于另一个 Windows 账户，git 会报 `safe.directory`。只在当条命令里临时放行，不要改全局 git 配置：`GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=safe.directory GIT_CONFIG_VALUE_0='*' <flutter命令>`。
  - 修复进度见 `02-项目进度.md` P1 #9。
- 国内镜像环境变量：`PUB_HOSTED_URL=https://pub.flutter-io.cn`，`FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn`。
- compileSdk 36：把 `android-app/compileSdk36.init.gradle` 复制到 `%USERPROFILE%\.gradle\init.d\`，解决 file_picker / image_picker / ML Kit 的构建问题。
- 常用命令（在 `android-app/` 下）：

```powershell
flutter pub get
flutter analyze --no-fatal-infos --no-fatal-warnings
flutter test --concurrency=1      # Windows 上必须串行，否则多个 Repository 测试抢同一个 SQLite 路径，报假失败
flutter run -d <设备ID>
```

- flutter 命令卡死：结束 dart 进程，删除 `C:\src\flutter\bin\cache\lockfile`。
- `flutter test` 接管道会吞掉退出码；要判断成败就把输出写到文件，再看 `$?`。

## 9. 真机连接

- 无线调试：手机「开发者选项 → 无线调试」，首次用 `adb pair IP:配对端口` 输入 6 位码配对，之后每次 `adb connect IP:端口`（小米端口经常变，以手机界面为准）。
- 小米报 `INSTALL_FAILED_USER_RESTRICTED`：打开「USB 安装」和「USB 调试（安全设置）」，必要时登录小米账号。
- 用户主力测试机：小米 15 Pro。

## 10. 常见坑

| 现象 | 原因 / 处理 |
|---|---|
| `Got socket error ... pub.dev` | 没设国内镜像 |
| `compileSdk ... requires version 36` | 没复制 compileSdk36 init 脚本 |
| 卡在 `assembleDebug` | Gradle 或依赖下载慢，检查镜像/代理 |
| APK 不能覆盖安装 | 签名不一致或 versionCode 变小，见 05 |
| 截图识别在 release 包崩溃 | R8 被打开了，恢复 `isMinifyEnabled=false` |
| 手机发烫 | 永动画或常驻多层 BackdropFilter |
| AI 键盘自动收回 | 焦点、路由、半屏 overlay 或空白点击拦截冲突，需要真机复查 |
| 小组件不显示 | 检查 provider、RemoteViews、snapshot、manifest、预览资源和刷新逻辑 |
| 跨月统计对不上 | 冲减类记录的日期没有归属原交易 |
