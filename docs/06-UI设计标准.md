# 肥喵记账 UI 设计标准（v1.7，2026-10-03 更新：资产总览批准规格）

> **任何新功能、新页面、新按钮，先对照这份标准，再写代码。**
> 标准来源：用户历次点名的参考（ChatGPT iOS 设置页、Cloudflare iOS 弹窗、iOS App Store、Claude 抽屉/改名弹窗、Telegram 分段胶囊、咔皮记账键盘）+ 已锁定的产品决策。
> 修改本标准需用户拍板；执行不需要——不符合就是 bug。

---

## 0. 三条总原则

1. **同类同设计、平台原生优先**：同一种交互在同一平台统一公共组件。§3 是 Android 标准件；iOS 对照 §3.1，原生设计更好的地方使用原生，尤其 Liquid Glass。两端保留功能、入口、信息层级和账务结果，不要求弹窗材质、菜单位置和系统排版逐像素相同。原生控件本身不因不同于 Android 就判违规（2026-10-02 用户明确）。
2. **非重点降号 + 变灰**（iOS 式层次）：说明、副标题、脚注必须比正文小一号且用灰阶——这是"有视觉重心"和"大杂烩"的分水岭。
3. **语义色是铁律不是主题**：收入=铜金 `kCatGold`、支出=中性 onSurface、危险/超支=橙 `AppColors.warning`、强调=主色蓝灰。**永远不用红；绿色唯一例外是预算健康态** `AppColors.budgetHealthy(scheme)`（浅色 `#7FB069`、深色 `#9AC584`），不得用于按钮、选中、成功、收入或其他状态；主题系统只开放背景与卡片质感。
   - **唯一红绿例外：统计页涨跌徽章**（总支出/收入/结余卡上的「↑↓ 百分比」）：好事绿 `#34A853`、坏事红 `#E5484D`，纯彩字无底色。2026-07-09 用户定「红绿更直观」，2026-09-30 用户确认保留。只限这个徽章，不得扩到别的组件。

## 1. 文字层级（代码：`theme/app_tokens.dart` 的 `AppType`）

| 层级 | 规格 | 用途 | 代码 |
|---|---|---|---|
| 页面标题 | 17 / w600 | AppBar（全局主题已管，**别手写**） | `AppBar(title: Text(..))` |
| 弹窗标题 | 16 / w500 左对齐 | 确认/表单弹窗 | ios_dialogs / ios_form 内置 |
| 行标题 | 15.5 / w500 onSurface | 设置行、编辑块标题 | `AppType.rowTitle` |
| 正文 | 15 / w400 onSurface | 一般内容 | `AppType.body` |
| 说明/副标题 | **13 / w400 / onSurface 55%** | 行副标题、选项说明、弹窗正文 | `AppType.secondary` |
| 分组标签 | 13.5 / w500 / 50% | 「管理」「显示」「接口」 | `SettingsSectionLabel` |
| 行尾值 | 14 / w400 / 55% | 「两位小数」「已配置」 | `AppType.trailingValue` |
| 脚注 | 12.5 / w400 / 45% | 页面底部整段说明 | `AppType.caption` |
| 金额/数字 | Nunito 字族，大小按场景 | 所有数字 | `fontFamily: 'Nunito'` |

**禁止**：裸 `Text('...')` 不带样式（默认 16px 深色=层次杀手）；`onSurfaceVariant`（深灰紫，没有灰的层次感，一律换 onSurface 灰阶）。

**资产总览特定规格（2026-10-03用户批准）**：主卡和四小卡左上标题统一15/w450/主题灰色及实际左边缘；主卡金额38，四小卡金额28/w800/无货币符号，读屏和主卡保留人民币说明。Android用局部Nunito静态800与中文可变450，新增family不改变原全局Nunito；字体许可必须随包。iOS用原生系统rounded金额与相近标题字重，保持信息层级，不为像素同款替换原生Menu/Chart。常规小卡两列、目标宽高5:3/最低106，200%及iOS辅助字号单列；主卡不含猫、不嵌小卡。

主图/四小图同时间范围（近3个月/近1年/全部），使用真实可比快照；左下百分比仅为区间估算变化，不是投资收益，缺可比数据用破折号而不是假0%。历史/口径断点不能跨连，缺历史收紧图高而不是补造曲线。坐标轴随字号留足空间，大字减刻度，日期/刻度不得裁切或重叠；金额遵循用户小数与舍入设置。其他页面字号、猫咪品牌、金额符号和资金/物品流程不因这条局部批准自动变化。

## 2. 颜色

- 灰阶：主文字 onSurface → 次要 55% → 最弱 45%（`AppTextColor.primary/secondary/hint`）。
- 语义：收入 `kCatGold` / 危险&超支 `AppColors.warning`（橙）/ 强调&选中 `scheme.primary`（蓝灰）/ 预算健康 `AppColors.budgetHealthy(scheme)`（唯一绿色例外）。
- 预算进度：健康绿 → 临界铜金 → 超支橙；未完成轨道必须取当前进度末端的同色低透明度，外缘同色略深，禁止退回灰色或白色底轨。
- 背景与卡片：一律 `AppColors.pageBackground(brightness)` / `AppColors.card(scheme)` / `selectedCard`——它们跟主题系统走，**别写死颜色**。
- 描边：`AppColors.hairline(scheme)`（别手写 black 6%，深色模式看不见）。
- 输入底：`AppColors.inputFill(scheme)`。

### 3.1 iOS 原生标准件

| 场景 | 优先实现 | 保留的肥喵要求 |
|---|---|---|
| 确认 / 删除 | 原生 alert / confirmationDialog；多段确认用 `appConfirmationDialog`（内部 `UIAlertController`） | 完整影响说明、取消不执行、防重与旧回调保护；共享确认框危险上下文用公开 tint 取橙色，取消为默认安全动作，不改系统内部子视图 |
| 选项 / 操作菜单 | 原生 `Menu`、`contextMenu`；共享 `AppSelectionMenu` | 选中标记、必要副标题、图标、VoiceOver；不固定 280pt 自绘浮窗 |
| 新建 / 编辑表单 | 原生 `sheet` + `AppThemedForm`（内部仍 `Form`） | 内容底色与行填充跟主题，原生输入/开关/Picker/键盘保留；不重排字段或改保存逻辑 |
| 导航 / 关键操作 | 既有 `LiquidGlassIconButton` / `LiquidGlassPillButton` | 单层玻璃、品牌强调色、可读标签与热区；不另叠背景仿造玻璃 |
| 日期 / 相册 / 文件 / 权限 | 系统原生控件 | 正确用途、名称、取消结果与权限反馈 |

- iOS 部署目标是 26.0，原生 Liquid Glass API 可直接使用；当前不引入未经确认的 iOS 27 专属 API。
- 系统负责原生弹层的材质、圆角、文字排版、动态字体及减弱动态/透明度适配。原生材质可以呈现系统中性色，不强制绘制一层与 Android 相同的实色背景；主题负责内容层、底图、有效明暗外观和品牌色。
- §1 的固定字号与 §6 中针对 Material/Android 自绘弹窗的禁令不用于覆盖 iOS 原生控件的系统布局。品牌素材、语义色和数据结果仍保持；不靠私有 KVC 修改系统弹窗颜色。

## 4. 页面模板

- **普通二级页**：`Scaffold(backgroundColor: transparent)` + `AppBar(leading: AppBackButton(), title: ...)`，经 `AppPageRoute` push（自带主题渐变底）。
- **设置类页**：ListView + `SettingsSectionLabel` 分组 + `SettingsGroup` 白卡 + 底部 `AppType.caption` 脚注（脚注左右 padding 24）。
- **全屏弹窗**（设置这种）：底部滑出 96% 高、圆顶角 28、右上 `AppCircleButton` ✕、无标题文字、主题渐变背景。
- **表单弹层**：`SheetHeader`（✕ 左上 + 居中标题 + 右上 `AppPillButton` 确认），**禁底部大长条确认按钮**。
- **多字段表单**：优先半屏弹层；每个输入框外套 `AppLabeledField`，字段名不能只靠会在输入后消失的 hint 表达。

## 5. 质感与动效

- 卡片：`AppColors.card()`（透明度跟主题，新用户默认浅色 80%；已保存的 40% 等偏好原样保留，不猜测成「未修改」后迁走）；圆角走 `AppRadius`（卡 20 / 大卡 28 / 胶囊 999）；分组卡用连续曲率。
- App 自有弹层内容、输入填充和分段底轨取同一主题来源：彩色主题用对应浅底，简约白用白底，深色提亮页面底色；不一律硬编码纯白或冷灰。分段控件保持胶囊形选中块，选中 w600、未选中 w400 且略淡（承接 10-01 已批准的在途方案）；默认 34dp/pt，大字场景必要时增长。iOS 原生弹窗外壳按 §3.1，不以残留原生控件数作为未完成数量；实际编译/截图边界见 `09`。
- 磨砂（BackdropFilter）只允许：瞬态弹窗（FrostedDialogCard）、iOS 菜单、底部输入卡、主页顶部渐隐（仅一层）。**禁常驻多层 blur、禁 `repeat()` 永动画**（发烫铁律）。
- 动效走 `AppMotion`（120/250/400ms），按压一律 `PressableScale`。
- 纯色/静态背景上的 GlassSurface 必须 `blur: 0`。
- 输入法/系统 inset 正在动画时，常驻大面积 `BackdropFilter` 必须用 `enabled: false` 暂停；不得通过替换祖先组件类型关闭模糊，以免重建 TextField、丢失焦点。
- 主题色卡固定单行展示；主题滑杆用 `CupertinoSlider`。普通进度条在浅色近白主题中的白色底轨必须回退为可见中性灰；预算进度不适用此规则，必须使用 §2 的动态同色轨道。
- 抽屉打开时主页必须有朝抽屉侧的定向阴影或发丝边界；导航图标统一使用 `AppLineIcon`，同组不得混用厚重 Material 图标。

## 6. 明令禁止（历史踩坑清单）

1. 裸 `AlertDialog` / `showDialog`＋Material 默认样式
2. 红色；预算健康态以外的任何绿色；`scheme.error` 当强调色
3. 底部大长条确认按钮（挪 SheetHeader 右上）
4. 手搓白圆按钮/开关/分段条（用标准件）
5. `IconButton`/`FilledButton` 裸用在导航位
6. `withOpacity`（用 `withValues`）；写死背景色（用 pageBackground/card）
7. `SnackBar`；系统 `showDatePicker`
8. 弹窗文字居中、实心色确认键（图二规范之前的旧样式）
9. `onSurfaceVariant` 当灰色用
10. 空状态放文案堆砌（只放猫）

## 7. 新功能上线前自查（5 问）

1. 用的都是 §3 标准件吗？有没有自己手搓的轮子？
2. 说明文字是不是 `AppType.secondary`/`caption`（降号+灰）？
3. 有没有出现红色、预算健康态之外的绿色、实心色按钮或居中弹窗文本？
4. 背景和卡片是不是走 `pageBackground`/`card()`（主题能跟上）？
5. 深色模式下看过一遍吗（描边/状态栏/文字可读）？窄屏（320dp）和 200% 字体下有没有溢出？

## 8. UI 改动交付：前后对比图

凡是调整了 UI 的批次，交付时必须同时提供：

1. 调整前的原始截图（保留在测试基线或 `test/failures`，不覆盖）；
2. 调整后的当前截图（来自最新截图回归输出）；
3. 前后左右并排的对比图；
4. 在两侧相同位置用编号框标出改动，图底部写明每个编号对应的改动内容；
5. 涉及多个页面时，再附一张总览联系图。

只允许拼接真实截图，不用概念图或 AI 生图代替；原始截图不得被标注层覆盖。页面没有可见变化时也保留该场景，并在图中写「保持一致」，不能把无变化报成改动。

- 输出目录：Android `android-app/outputs/ui_comparisons/<日期>/`；iOS `ios-app/outputs/ui_comparisons/<日期>/`。iOS 没有 Mac 实际采集时必须写「前后图未验」，不拿 Android Widget 图、概念图或未运行的截图测试代替。
- 生成脚本：`android-app/tooling/make_ui_comparisons.py`（固定映射），以及按批次写的 `make_*_comparison.py`
- Windows 离屏截图必须注册与真机一致的字体（Nunito + Noto Sans SC 中文回退 + MaterialIcons + CupertinoIcons），否则中文和图标会显示成方框。

## 9. 双端品质目标与反复验收（2026-10-03 用户确认）

### 9.1 目标与边界

以 **Awwwards、The Webby Awards、FWA 获奖作品的完成度**作为 Android/iOS 长期品质目标：不仅首屏好看，阅读、操作、异常处理、动效、性能和品牌细节也要经得起反复使用。每批主动自查、修正、复验，不能满足于「代码改了」或「测试绿了」。

这是肥喵的内部品质目标与验收方法，**不是这三个奖项的官方评分表，也不保证实际获奖**；不以自评高分、截图数量或 CI 全绿代替实际体验证据。

- 财务 App 优先数据正确、隐私可靠、记账高效，再提升视觉；不照搬展示型网页的大动画、营销式排版或装饰性玻璃。
- 保留蓝白英短猫品牌、语义色、主页＋抽屉及已锁定决策。品质目标不自动授权重做页面、改统计口径、隐藏当前自用 AI 配置、推送或发布。
- 双端达到同样的产品完成度，不强求相同外壳。iOS 原生效果更好的地方依 §3.1 使用原生，包括 Liquid Glass；不因与 Android 不同就重画系统控件。

### 9.2 每批六项自查

| 维度 | 要检查什么 | 最低证据 |
|---|---|---|
| 视觉与阅读 | 信息重心清晰；同类字号、间距、对齐、图标一致；主题自然；长标题、金额、表格和附件不挤压或裁切；完整页面与组件都成立 | 当前源码的同场景前后图及人工复看；浅/深主题、受影响彩色主题、窄屏和大字号；不只看精挑的一张图 |
| 完整交互流程 | 正常、空态、加载、成功、失败、重试、取消、编辑、删除/恢复；键盘、焦点、返回、重复点击与重启结果正确；用户不会进入无反馈的死路 | 相关测试＋可用平台上的真实流程；写库/删除/恢复等操作核对实际持久化结果，不只看提示 |
| 反馈与动效 | 跟手、自然、克制；开始/完成/失败有明确反馈；弹层打开关闭、拖动回弹、键盘过渡不跳变；需要时有触觉；减弱动态时仍可理解 | 实际操作或录屏，注明设备/系统；静态图不能证明动效或震动通过，不为效果加入永动画或多层常驻 blur |
| 性能与稳定 | 点击到完整首页（数据全部展示）、关键操作响应、列表滚动、长聊天和附件处理；无卡顿、闪退、重复请求或无谓耗电 | 同设备、同数据、同构建模式的改前/改后实测；记录系统、刷新率、冷/热启动、测量次数和慢次，先定本批指标再改；不能用更快设备或占位首屏冒充提升 |
| 可访问性与适配 | 实际叠色后的正文/次要文字/按钮可读；信息不只靠颜色；屏幕阅读器名称、顺序和焦点；动态字体、减弱动态/透明度、安全区和热区不互相遮挡 | 对比度检查＋大字/窄屏截图＋可用设备的辅助功能操作；iOS 优先系统适配；涉及已定字号、灰阶或热区策略的变更先与用户对齐，不借此强制推翻 48dp 建议 |
| 品牌与内容 | 猫咪素材清晰；图标风格统一；中文、日期、金额和状态文案准确；不混杂英文或缺字；失败原因与恢复入口易懂；无重复提示或多余留白 | 全页人工复看，覆盖空/有数据、长内容和失败场景；核对资源实际渲染与文字，不把概念图当生产效果 |

同一项可以标「不适用」，但须写理由；没有设备或结果时标「待验证」，不能标通过。测试对主文字取色通过，不代表所有灰阶文字、透明背景组合或原生菜单都通过。

### 9.3 自查 → 修正 → 复验

1. **固定基线**：记录源码提交及在途改动、场景/数据、日期、主题浓度、语言、屏幕逻辑/像素尺寸、字号、系统与构建模式；保留真实改前图，不靠缩放原图制造同尺寸。
2. **完整检查**：按六项检查当前受影响组件与页面，列具体问题、复现条件、影响和验收办法；修正前先确认是实际缺陷，不把平台原生差异当问题。
3. **小批修正**：优先数据/流程风险和裁切、重叠、不可读、失焦等问题，再处理视觉细节；同类问题在公共组件解决，避免只修一个页面或扩大无关改动。
4. **重新验收**：修后重新运行受影响测试、操作流程及采图，按 §8 提供编号前后对比；再以审查者视角复看完整页面和边界，不只看改动位置。发现回归继续修正，不能删断言或调宽截图容差来放行。
5. **记录结果并继续迭代**：在 `02` 登记通过/待验/问题，在 `10` 写实际改动与证据。缺 Mac、真机、权限或最终 CI 结果时保留未验状态，说明下一步；不无限盲跑，也不因环境受限降低标准或宣称完成。

### 9.4 何时可以说完成

- **组件完成**：该组件本批相关的功能、主题、长内容/大字和交互都已验证；组件离屏图仍不能代替其所在页面的验收。
- **批次完成**：当前范围无未解决的 P0/P1、裁切、重叠、不可读或核心操作失败；相应测试、真实流程、前后图、性能/辅助功能检查已取得适用证据。未验的门不能按通过封板，非阻塞遗留问题列明影响和后续安排。
- **全 App 品质目标**：逐页和跨页核心流程都覆盖后，才能讨论整体完成；单批公共组件、Android 通过、原生编译或旧基线成功，均不代表全 App 或双端达标。实际评奖结论不由内部检查宣告。
