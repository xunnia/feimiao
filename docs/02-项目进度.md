另两项必须与用户讨论，而不是直接改公式：

- **「匀」覆盖完整自然周期的语义修订正在讨论。** 纯 Dart 实测月预算 3000 + 整月特别安排 1000，校验通过、月总额为 1000；每天 100 + 单日特别安排 50，10 月总额为 3050。最初审查按旧合同「周期总额不变」建议拦截。用户 10-02 补充：后来设置的整月特别安排应覆盖旧月预算，1000 元就是当月预算，不需要拦截。因此该结果不能继续直接称为计算 bug；建议区分「部分日期重新分配，周期总额不变」与「完整周期临时覆盖，采用安排总额」，安排结束后回到原日常规则。日/周/年及多安排联合作用等完整边界还未确认；此处没有修改 §08 正式合同或引擎。
- **核心同步不是完整资产同步。** 后端已定 v1 暂不传预算、资产、校准和聊天；账户余额/净资产可能因本机校准不同而不同，这个阶段限制已被接受，不再要求用户重选方向。但「云端覆盖本机」删除了本地资产所引用账单时如何处理仍待定，必须在允许覆盖前补合同，不能留悬空引用。

### 7.4 方案判断：保留方向，改变推进和验收方式

1. **保留本地优先、少决策的记账核心。** 主流程是记下来、看清花费、安排预算、核对资金、可靠找回数据；AI 是帮助用户完成这些任务和答疑的入口，不是让离线记账依赖账号或网络。
2. **保留预算规则方向。** 大日历 + 日常 / 特别安排 + 默认每月重新开始，比恢复分类限额、专项追踪和固定预留更符合当前目的。补边界与预览，不重新塞回已经删掉的概念。修改既有日常规则会重算历史、新增规则从该月 1 号接替，都是既定设计；只讨论如何把影响月份和变化金额说清楚。
3. **保留资产三视图和数据诚实原则。** 资金与物品不要混成一张大清单；日均持有花费不是利用率或收益。既有校准、事件、可信核对继续复用，复杂投资和自动估值仍暂缓。
4. **不做大重写。** Flutter、SQLite、纯计算引擎、共享 AI Transport 和现有事务写账是可用基础。大文件本身不是改架构的充分理由，优先按已经出现的风险抽出边界，保留旧 API 适配入口。
5. **不再按「一页画完」判定交付。** 每批解决一条完整操作链；例如新建规则、预览、保存、重启读回、编辑账单后首页/统计/Widget 同步，才是预算闭环。不能只截静态页面、只检查 CI 绿灯。

建议逐步收口的边界（提案，不是已完成）：

| 边界 | 负责什么 | 不做什么 |
|---|---|---|
| 异步任务上下文 | 固定账本、账号、数据库代次、任务身份、模型/强度，提交前校验 | 不读取页面后来切换的「当前账本」替代发起归属 |
| 财务只读投影 | 家族净额、账户移动、预算、资产各自的日期轴、范围与质量状态 | 不让页面、Widget、AI 各自复制公式；不混淆预算余额和现金余额 |
| 媒体与恢复服务 | 媒体归属、相对路径、manifest、完整恢复点、持久恢复阶段 | 不只备份 DB；不靠进程内布尔值处理被杀后的恢复 |
| 账号会话服务 | 令牌轮换、旧响应隔离、缓存归属、换账号停传 | 不把登录状态、权益、AI 接收方同意混成一个开关 |
| 不可变主题与标准件 | 统一色值、文字、标题、弹层、菜单、输入与反馈 | 不在多个静态全局字段里暗改主题；不以全局增透明度代替页面设计 |
