# 肥喵记账小组件市场分析与产品方案

> 状态说明：用户提出本分析要求前，`widget_feimiao.xml` 曾被改成一版“主页大卡片化”的未构建草稿。该草稿不能视为最终方案；后续实现应以本报告的多样式矩阵重新设计和验收。

## 1. 外部原则

Android 官方把小组件定义为用户桌面上的 “at-a-glance” 信息入口：展示 App 最重要的数据和功能，并允许用户按桌面空间调整信息量。官方也把小组件分成信息型、集合型、控制型、混合型四类；财务类小组件通常应是“信息 + 控制”的混合型，而不是完整报表。

关键约束：

- 小组件不是 App 页面缩略图，而是“信息零食”，App 才是完整正餐。
- 小尺寸只展示核心信息；尺寸变大后再增加上下文。
- 桌面交互受限，主要是点击和垂直滑动，不能依赖复杂手势。
- 应提供快捷导航，尤其是“新建内容”这类生成动作。
- Google Play 2025 年开始强化小组件发现能力，说明高质量小组件会直接影响用户发现、留存和桌面占有率。

参考来源：

- Android App widgets overview: https://developer.android.com/develop/ui/views/appwidgets/overview
- Android Developers Blog, Google Play enhances widget discovery: https://android-developers.googleblog.com/2025/03/google-play-enhances-widget-discovery.html

## 2. 主流记账小组件模式

结合主流记账/预算产品、用户提供的咔皮参考图、以及肥喵当前能力，小组件大致可归为 6 类。

| 类型 | 主目标 | 常见展示 | 适合尺寸 | 适合用户 |
| --- | --- | --- | --- | --- |
| 快捷记账 | 降低记账摩擦 | `+`、支出/收入/转账/AI 快记入口 | `1x1` / `2x1` | 高频记账用户 |
| 今日支出 | 快速看当天花了多少 | 今日支出、今日可花、剩余可用 | `2x1` / `2x2` | 每天控预算用户 |
| 月预算 | 判断还能不能花 | 预算剩余、已用进度、今日建议 | `2x2` / `4x2` | 设置预算用户 |
| 月度概览 | 桌面看大盘 | 本月支出、收入、结余、趋势文案 | `4x2` | 普通记账用户 |
| 分类洞察 | 知道钱花在哪 | 本月前三分类、占比、进度条 | `4x2` / `4x3` | 分析型用户 |
| 资产净值 | 看资产健康 | 净资产、账户余额、负债、变化 | `2x2` / `4x2` | 使用资产管理用户 |

市场共性结论：

- 做得好的小组件不会把 4-6 个指标平均排布；通常只有一个主指标。
- 预算型小组件最有价值，因为它能回答“现在还能不能花”。
- 快捷入口必须存在，否则小组件只是在桌面上占位置。
- 分类排行适合中大尺寸，不能塞进所有小组件。
- 隐私模式是刚需，桌面金额必须能隐藏。
- 小组件要允许用户选择账本/周期/显示内容，否则一个默认样式很难满足所有人。

## 3. 肥喵自己的小组件矩阵

### 3.1 MVP 第一批

第一批建议做 4 个样式，覆盖高频场景，不要一开始就铺太多。

#### A. 快记入口 `1x1`

用途：替代 App 图标，点一下直接记账。

内容：

- 肥喵图标或 `+`
- 文案：记一笔 / AI 记账

点击：

- 主区域：打开 AI/手动记账弹层

验收：

- 桌面上比普通 App 图标更有理由保留。
- 不显示金额，天然无隐私风险。

#### B. 今日可花 `2x2`

用途：用户买东西前看一眼今天还能花多少。

有预算时：

- 主指标：今日可花
- 辅助：本月预算剩余
- 进度：本月预算已用条
- 动作：`+`

无预算时：

- 主指标：今日支出
- 辅助：本月支出
- 动作：`+`

验收：

- 3 秒内能知道今天还能不能继续花。
- 不能出现三行以上复杂列表。

#### C. 月预算卡 `4x2`

用途：用户桌面上的主力小组件，视觉应接近主页大卡片。

有预算时：

- 左上：账本名 + 日期
- 主指标：预算剩余 / 已超预算
- 辅助：已用金额 / 预算总额
- 中部：预算进度条
- 底部：今日可花、本月收入、本月支出
- 右上：`+`

无预算时：

- 主指标：本月结余
- 辅助：本月收入 - 本月支出
- 底部：今日支出、本月收入、本月支出

验收：

- 视觉上像“肥喵主页大卡片”，不是统计报表。
- 只有一个最大数字。
- 预算条和金额必须有明确主次。

#### D. 分类洞察 `4x2` 或 `4x3`

用途：满足“钱花在哪”的分析型需求。

内容：

- 主指标：本月支出
- 右侧或底部：前三一级分类
- 每类：图标/名称/金额/占比/细进度条
- 点击分类：进入分类明细

验收：

- 分类最多 3 条；超过 3 条不在桌面展开。
- 不能和月预算卡混在一个小组件里。

### 3.2 第二批

后续再做：

- 资产净值 `2x2` / `4x2`
- 最近账单 `4x2`
- AI 问答摘要 `4x2`
- 储蓄目标进度 `2x2`
- 多账本切换配置

第二批的前提是第一批真机验证稳定、桌面尺寸适配明确。

## 4. 数据分析口径

小组件要比 App 页面更克制，所有数据都要围绕“用户当下决策”。

### 预算优先级

若用户设置了预算：

1. 主指标优先显示“预算剩余”或“今日可花”。
2. 支出/收入/结余降为辅助。
3. 分类排行只在专门的洞察小组件显示。

若用户未设置预算：

1. 主指标显示“本月结余”或“今日支出”。
2. 提供温和提示：设置预算后可显示今日可花。
3. 不要显示空预算进度条。

### 金额隐私

隐私模式应同时影响：

- 主金额
- 底部指标
- 分类金额
- 最近账单金额

但可以保留：

- 百分比
- 预算进度条
- 趋势状态：正常 / 偏快 / 已超

### 刷新与可信度

必须显示更新时间或相对更新：

- `刚刚更新`
- `20:42`
- `打开 App 后更新`

如果数据超过一定时间未刷新，应降低可信度：

- `数据可能不是最新`
- 点击刷新或打开 App

## 5. 当前小组件 UX 审核

用户截图中的当前小组件问题非常明确：

1. 信息过载  
   一个 `4x2` 卡片里同时塞了今日、本月支出、收入、结余、预算剩余、预算条、分类排行 3 条。每个信息都像重点，结果没有重点。

2. 层级错误  
   “预算剩余”本应是主指标，但现在只占一行普通文字。用户需要扫完整张卡才能知道当前预算状态。

3. 太像报表  
   分类排行适合统计页，不适合默认桌面小组件。桌面小组件应该服务即时决策，不应该复制统计卡。

4. 审美不统一  
   当前白底、黑条、密集表格式排版与肥喵主页大卡片的柔和层级不一致，也不像用户偏好的 iOS/GPT 式轻量卡片。

5. 空间效率差  
   四列指标横排导致每个数字都很小，中文标签和金额都挤，桌面远距离看不清。

6. 快捷动作弱  
   `+` 有，但视觉上像一个孤立按钮，不像“快速记账入口”。用户不会第一眼知道它是核心动作。

7. 多样式缺失  
   只有一个样式，用户不能选择“快捷记账 / 今日可花 / 月预算 / 分类洞察”。这会导致任何一个样式都被迫承载所有需求。

## 6. 肥喵小组件设计标准

统一规则：

- 每个小组件只能有一个主任务。
- 每个小组件只能有一个最大数字。
- 默认不展示超过 3 个辅助指标。
- 分类数据只出现在“分类洞察”样式。
- 桌面卡片要接近主页大卡片，而不是统计页报表。
- `+` 是核心动作，必须清晰可点。
- 必须支持隐私模式。
- 必须支持不同尺寸的信息递进。

视觉建议：

- 背景：柔和浅暖白或系统材质感，避免纯死白。
- 圆角：大卡片 22-26dp。
- 主金额：28-34sp，接近主页数字字体气质。
- 标签：10-12sp，字重不超过 w400。
- 主标题：14-15sp，w500。
- 辅助金额：12-14sp，w500。
- 颜色：黑/灰为主体，预算正常用柔和绿，警告用橙，不要用大面积黑条。

## 7. 推荐实现顺序

1. 暂停单一万能小组件。
2. 保留 Flutter 快照层，但扩展字段：
   - `primaryMode`
   - `heroLabel`
   - `heroAmount`
   - `heroHint`
   - `statusText`
   - `updatedText`
   - `metrics[]`
   - `categories[]`
3. Android 原生先实现 3 个 layout：
   - `widget_quick_add_1x1`
   - `widget_budget_2x2`
   - `widget_overview_4x2`
4. 第二步再实现：
   - `widget_categories_4x2`
   - `widget_assets_2x2`
5. 每个 layout 用独立 `appwidget-provider` 或同 provider 不同 initial layout；避免一个 XML 兼容所有尺寸导致失控。
6. 构建后必须真机验证：
   - 小米桌面 2x2 / 4x2 添加效果
   - 长按缩放后的内容裁切
   - 隐私模式
   - 点击 `+` 是否直达记账
   - 打开 App 后数据是否刷新

## 8. 结论

当前小组件不应该继续微调。它的问题不是字号或颜色，而是产品架构错误：用一个小组件承载了预算、概览、分类、快捷入口四类任务。

正确方向是“小组件家族”：

- 快记入口负责动作。
- 今日可花负责日常消费决策。
- 月预算卡负责桌面主视觉。
- 分类洞察负责分析。
- 资产净值负责资产管理。

第一版应优先做 `1x1 快记入口 + 2x2 今日可花 + 4x2 月预算卡`。这三种做好，比一个塞满数据的万能小组件强很多。
