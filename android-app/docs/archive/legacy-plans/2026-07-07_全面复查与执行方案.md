### 1.0K 1.125.0+127 最新补充：AI 输入法闪退去强制 show 修复

本轮继续处理用户反馈的“AI 记账点击输入框后，输入法弹出瞬间又没有了”：

- 相关文件：`lib/views/home/ai_chat_panel.dart`、`test/ai_chat_panel_focus_test.dart`
- 复盘结论：旧方案虽然已经减少了 `unfocus -> requestFocus`，但仍保留多轮 `TextInput.show` 和键盘可见性 timer。小米/MIUI 在 IME 启动动画期间对输入连接很敏感，应用反复补发 show 可能会让系统重置输入连接，表现为输入法刚弹出又消失。

  - 移除 `SystemChannels.textInput.invokeMethod('TextInput.show')` 及相关键盘可见性 timer。
  - 保留有限次数 FocusNode 修复，只处理“焦点真的丢了”的情况。
  - `didChangeMetrics()` 不再硬拉键盘，只在保护期内补回焦点。
  - 空态 AI 记账不再用 `MediaQuery.viewInsets.bottom` padding 挤压整棵面板，改为只让建议区和输入框随键盘高度局部上移，减少 TextField 输入连接被整树重排打断的概率。
- 已通过：`flutter analyze --no-pub`、`flutter test test/ai_chat_panel_focus_test.dart` 6 项、全量 `flutter test` 261 项、`flutter build apk --release`、`aapt dump badging`、`apksigner verify --print-certs`。

  - `_onFocusChanged()` 丢焦时不再立刻 post-frame 强拉键盘，只排入有限修复流程。

### 1.1 AI 记账输入框键盘闪退

问题：AI 记账模式点击输入框后，输入法弹出瞬间又消失。

原因：同一个输入框存在多条焦点路径：

- 面板激活后 `_syncActiveState()` 延迟 `requestFocus()`。
- 空态输入框自身 `TextField.autofocus`。
- 输入框外层点击再次 `requestFocus()`。
- 键盘弹出后 `viewInsets` 变化触发布局重建，`autofocus` 与延迟焦点请求互相抢焦点。

已改：

- `lib/views/home/ai_chat_panel.dart`
- 移除输入框对 `autofocus` 的依赖。
- 增加 `_requestInputFocus()`，统一焦点请求入口。
- 增加 160ms 焦点请求防抖，避免键盘弹起期间重复抢焦点。
- 二次复核后继续增强：
  - 点击输入框或自动聚焦后进入 1100ms 焦点保护期。
  - 保护期内背景遮罩点击只忽略，不再 pop 面板或二次抢焦。
  - 增加 260ms 焦点保活计时器；若 Android IME 打开期间因为面板重布局误丢焦点，会绕过 160ms 节流补一次 `requestFocus`。
  - 发送、切换手动记账、主动点背景收键盘、面板 inactive 时都会清掉保护期，避免键盘被粘住。

验收：

- `flutter analyze --no-pub` 通过。
- `flutter test` 通过。
- 仍需真机/模拟器点击 AI 记账输入框验证键盘是否稳定停留。

## 2. 小组件重做方案

已有文档：`docs/widget_market_analysis.md`。

当前判断：

- 当前小组件最大问题不是单个字号，而是职责混杂。
- 桌面小组件应服务“快速判断”和“快速行动”，不应把统计页缩小塞进去。
- 总览小组件已先收敛为主页大卡片式核心信息：本月支出为唯一主数字，收入/结余/今日为底部辅助指标。
- 旧预算进度块已从默认总览小组件隐藏，预算/同期对比后续应作为独立小组件，不再混塞进总览。

优先做 4 种：

1. `1x1 快记入口`
   - 主任务：快速记一笔。
   - 内容：一个加号/猫爪图标 + “记一笔”。
   - 点击：直接进 AI/手动记账入口。

2. `2x2 今日可花`
   - 主任务：今天还能花多少。
   - 内容：今日可用、预算剩余、今日已花。
   - 适合设置预算的用户。

3. `4x2 月度概览`
   - 主任务：复刻主页大卡片。
   - 内容：本月支出、收入、结余、预算进度、快捷记账按钮。
   - 不放分类排行，避免信息过载。

4. `4x2 同期支出对比`
   - 主任务：回答“这个月到今天花得正常吗”。
   - 内容：
     - 本月截至今日支出。
     - 历史月份同进度平均支出。
     - 月度条形对比图。
     - 当月前三支出分类。

执行优先级：

1. 先把已有 `widget_budget` 改成“月度概览/今日可花”其中一个，不再显示旧“预算余量”风格。
2. 保留 `widget_feimiao` 作为 4x2 主小组件。
3. 再新增同期对比小组件，避免一次性增加太多 RemoteViews 复杂度。

验收标准：

- 桌面上每个小组件只能有一个最大数字。
- 小组件不能出现密集表格。
- 字号层级：主数字 24-30sp，一级标签 12-15sp，辅助文字 9-11sp。
- 任何 2x2 小组件最多 3 个指标。

## 3. 资产管理学习“有数”模式的计划

说明：没有拿到可靠公开资料时，不应假装复刻“有数”。以下以成熟资产管理产品通用模型为基础，再结合肥喵当前账本能力设计。

### 3.1 资产管理应回答的问题

- 我现在净资产是多少？
- 现金、银行卡、负债分别是多少？
- 这个月净资产变多还是变少？
- 哪些账户余额异常？
- 哪些账单影响了账户余额？
- 信用卡/花呗/贷款什么时候要还？

### 3.2 数据模型

账户表需要扩展：

- `account_type`：现金、银行卡、信用卡、储蓄卡、支付账户、投资、贷款、应收、其他。
- `balance`：当前余额。
- `opening_balance`：初始余额。
- `currency`：币种。
- `include_in_net_worth`：是否计入净资产。
- `credit_limit`：信用额度。
- `billing_day`：账单日。
- `repayment_day`：还款日。
- `institution`：银行/平台。
- `archived`：是否归档。

新增资产快照表：

- `id`
- `account_id`
- `snapshot_date`
- `balance`
- `created_ms`
- `source`：手动、账单自动、导入、同步。

### 3.3 页面规划

资产首页：

- 顶部：净资产、较上月变化。
- 第二层：资产、负债、现金流入流出。
- 账户列表：按类型分组，显示余额、变化、是否异常。
- 风险提醒：信用卡还款、负债比例、余额过低。

账户详情：

- 当前余额。
- 余额趋势图。
- 近期交易。
- 快速调账。
- 账单日/还款日设置。

负债中心：

- 信用卡/贷款/花呗等统一展示。
- 本月应还、最低还款、还款倒计时。
- 支持设置提醒。

资产分析：

- 净资产趋势。
- 资产结构饼图。
- 负债率。
- 流动性覆盖天数。

### 3.4 和记账系统的关系

- 每笔收入/支出影响账户余额。
- 转账影响两个账户余额，但不影响收支。
- 不计入收支的账仍可影响账户余额，例如理财买入、还款。
- 调账只改变余额，不进入收支统计。

### 3.5 风险点

- 用户导入历史账单时，如果没有准确账户，余额会错。
- 信用卡消费是负债增加，不应简单当现金减少。
- 投资资产需要价格波动，不应和现金账户混算。
- 多币种要先不做，避免汇率问题扩大。

## 4. 定时记账优化计划

当前应补能力：

- 周期规则预览：创建时显示未来 3 次发生日期。
- 到期行为：
  - 自动入账。
  - 生成待确认。
  - 仅提醒。
- 支持跳过本期。
- 支持延期本期。
- 支持结束日期。
- 支持“工作日顺延”。
- 支持规则暂停。

UI 标准：

- 新增/编辑定时记账使用统一半屏：
  - 左上角关闭。
  - 标题居中。
  - 右上角保存。
- 分类选择必须和手动记账分类选择一致。
- 循环图标应统一为线性图标，避免廉价感。

验收：

- 新建规则后，主页或定时记账页能看到下一次执行时间。
- 到期生成的账单能追溯到规则 id。
- 删除规则不删除已生成账单。

## 5. 自动记账方案

推荐分三期。

### 5.1 P0：通知识别待确认

权限：

- Android 通知读取权限。
- 清楚解释只读取支付通知，不上传原文，用户可关闭。

流程：

1. 监听微信、支付宝、银行等通知。
2. 本地解析商户、金额、时间、支付方式。
3. 生成“待确认账单”。
4. 用户确认后入账。
5. 用户修改分类后写入 AI/规则记忆。

去重：

- 使用通知包名、通知时间、金额、商户、原文 hash。
- 10 分钟内相同 hash 不重复。
- 同金额同商户但不同时间不能误删。

### 5.2 P1：高置信自动入账

条件：

- 商户历史分类稳定。
- 金额和时间可信。
- 非退款/转账/红包等复杂类型。

行为：

- 自动入账。
- 通知用户“已记一笔，可撤销”。
- 保留撤销入口。

### 5.3 P2：截图/OCR/账单导入联动

- OCR 识别支付截图。
- 批量识别账单截图。
- 自动和已有通知记录合并去重。

风险：

- 通知读取是高敏权限，隐私文案必须非常清楚。
- 自动入账必须有撤销，否则用户不信任。
- 解析失败不能静默丢弃，要进待确认列表。

## 6. Pro / Max 会员方案

### Free

- 本地记账。
- 基础统计。
- 每月少量 AI 记账/问账次数。
- 手动备份/导入导出。
- 基础小组件。

### Pro

- 更高 AI 次数。
- 月报/周报/年报。
- 自动记账待确认。
- 高级统计卡。
- 自定义图标/分类高级管理。
- 多账本高级模板。
- 更多小组件样式。

### Max

- 大量 AI 次数。
- 深度报告和长期趋势分析。
- 高置信自动入账。
- 云同步/多设备。
- 高级资产管理。
- 预算预测和异常提醒。
- 优先模型，如 DeepSeek-V4-Pro 或后续更强模型。

### AI 次数控制

- 服务端维护用户额度。
- 每次 AI 请求先扣预估额度，失败返还。
- 报告类按高成本计费。
- 本地手填 API Key 可以作为高级入口，但要和会员权益区分：自带 Key 用户只承担模型费用，不等于解锁云同步/自动记账等产品能力。

### 收款方案

国内 Android：

- 应优先考虑应用商店内购/订阅或合规第三方支付。
- 如果走官网/小程序收款，要注意各应用市场规则。

海外：

- Google Play Billing。

不建议：

- 直接个人微信/支付宝收款后手工开会员。维护成本高，容易出错，也不利于退款和合规。

## 8. 代码审计重点

### 统计口径

- 退款必须挂回原单。
- 不计入收支的账不能进入统计/预算/洞察。
- 转账不能进入收入/支出。
- 导入重复判断必须依赖 UUID 或来源订单号，不能用“金额+商户+时间”粗暴去重。

### AI

- 报告生成不能因为切页面而丢失。
- 报告失败应写入本地兜底报告，不应只提示“没连上 AI”。
- 报告语气不能制造恐慌。
- 报告 Markdown 不应使用表格，旧表格要在阅读器降级渲染。

### 权限与隐私

- API Key 本地保存需要安全存储。
- 自动记账通知读取必须有单独授权说明。
- AI 发送账本内容前必须有隐私确认。

### 性能

- 大量账单导入后，抽屉/首页不能每帧重新汇总全量数据。
- fl_chart 等重组件应懒加载/加 RepaintBoundary。
- 模糊效果要避免实时大面积高 sigma，必要时降采样或静态缓存。
