## 一、总诊断

底子是「数据诚实性做到极致的审计后台」，套了层猫系 App 的壳。数据能力（净额/质量口径/审计链）非常扎实，但视觉气质与主页/统计页**断裂**：主页是「大数字 + 猫 + 铜金点缀」，资产页是「小数字 + 表格 + 免责声明」。四个系统性病灶：

1. **数字没有主角**：净资产 hero 卡里 6 个指标同字号同灰度平铺（净资产/资金资产/计入物品/资金净值/总负债/总资产），三个近义概念并排，无视觉重心。
2. **内部术语裸奔**（20+ 处）：「按已知金额」「12/12 项计入 · 全局人民币口径」「自动计算，不代表完整核对」「还没有冻结过完整资产证据」「较上一可比点」「计入口径待确认」「含历史推定数据」「绝对锚点」——工程侧 MetricStatus 直接序列化成 UI 文案怼在用户脸上。
3. **卡片规格失控**：同一页并存圆角 8/16/18/20、三种卡片质感（阴影卡/描边卡/裸卡）、两种分隔线、六种图标底透明度魔法数。
4. **无情感化**：无猫（除资金空态）、无铜金点缀、图表素得像 demo；物品网格空态是纯文字（违反「空态只放猫」）。

**已实锤的 bug**：物品网格卡底部一行文字被固定宽高比裁切成碎块（见 05_items.png，深红色碎条）；权益逾期文字用 `scheme.error` 红色（accounts_view.dart:2568，违反配色铁律）。

## 二、P0 快赢批（纯观感与文案，不动数据模型，约 1 天）

1. **术语人话化全扫**（替换表，逻辑不动）：
   - 「净资产（按已知金额）」→「净资产」（口径说明收进 ⓘ 点开）
   - 「12/12 项计入 · 全局人民币口径」→ 删除（全部计入时不显示，有排除时才显示「3 项未计入 ›」）
   - 「自动计算，不代表完整核对」→「自动估算」
   - 「还没有冻结过完整资产证据。」→「还没做过完整核对」
   - 「较上一可比点」→「较上次」
   - 「计入口径待确认」等质量标签 → 小胶囊/圆点图标 + 点开才展开人话解释
2. **净资产卡重排**：主数字放大（≥30px Nunito 加铜金细节），5 个次级指标降两级（13px 灰、两行网格或「查看构成 ›」收起）；总负债保持橙。
3. **卡片规格统一**：圆角全走 `AppRadius`（卡 20）、质感统一 `AppColors.card()` + 一种描边策略、分隔线统一、图标底透明度收成常量。
4. **修 bug**：物品卡底行裁切（高度自适应或删行）；`scheme.error` 红 → `AppColors.warning` 橙。
5. **噪音清理**：「· CNY」后缀全删（App 只有 CNY）；账户行副标题最多 2 段。
6. **标准件补课**（规范审计 21 条中的机械项）：删 `_SwitchRow` 换 `SettingsRow+AppSwitch`；三张表单（权益/账户/收回）铺 `AppLabeledField`；`_TypeChip` 选中态改主色+PressableScale；空态补猫（物品网格/两个弹层）；删手写 `centerTitle`；币种只读字段别放 hint 里。

## 三、P1 结构批（✅ 2026-07-27 已全部完成并验收，v1.206.0+208 / b0727-208；实际落地以 CLAUDE_HANDOFF_CURRENT.md P1 段为准——含用户补拍板：资金页筛选行整行删除、筛选控件降级轻量「文字+⌄」、¥ 符号改 onSurface、账户/权益详情全屏页修真机白底状态栏 bug）

2. **资金页**：分组头加小计金额；¥0 账户收进「已清零」折叠；权益行副标题瘦身。
3. **物品页筛选收口**：分段+计数行+2 下拉+搜索+分类 pill 五层 → 搜索框 + 一个筛选行（分段保留）。
4. **详情容器统一**：账户/权益详情（半屏弹层）与物品详情（全屏页）统一为一种模型；物品 ⋯ 菜单 13 项分层（编辑/常用置顶，报废/丢失/赠送/撤销类收进「更多操作」二级）。
5. **新增入口统一**：右上 ＋ 在三个 tab 行为一致；「从账单加入物品」缩短为一步直达。
6. **「生成报告」反馈闭环**：生成后直接打开或给跳转入口，别只 toast。
